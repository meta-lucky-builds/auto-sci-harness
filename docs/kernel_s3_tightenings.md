# Kernel tightenings on branch s3-kernel (2026-10-09)

## 1. Duplicate JSON keys (STATUS §3.5 "suspected", now proven and fixed)
Python's `json` keeps the LAST value of a duplicated key; other readers (and people) often see the FIRST. A document
with a duplicated key is two documents. Proven on a7fb608: an LP problem stating `"c":["100","100"],"c":["1","1"]`
was CERTIFIED-EXACT for the last `c` while a first-value reader sees a problem whose optimum is 260
(`tests/test_kernel_dupkeys.py`, fail-first log `scratchpad/logs/dup_failfirst.log`).
Fix: every JSON the Kernel parses goes through `claim.strict_json` (object_pairs_hook refusing duplicates at any
depth): evidence records, predictions, earlier certificates, `Kernel.certificate`, ledger entry bodies and anchors,
bundle manifests, bundled payloads. The adapters' own parsers (`lp.py`, `formal.py`; `sim.py` already did) refuse
duplicates with their own hook, so their identity does not grow to include the core. `kerneld/protocol.py` (stdlib
only by design) has its own hook. Checked and NOT changed: `kerneld/releases.py` and `kerneld/campaign.py` (parse
rows/cassettes the host itself wrote), `verify/lean_validation.py` (its own fixture), `store/blobs.get_json` (not
Kernel code; the Kernel no longer calls it). Museum: `JSON-DUP-LP`, `JSON-DUP-KERNEL`.
**The `lp` and `lean` adapter hashes change: the human must re-run `chh approve-adapter lp` (and `lean` once usable).**

## 2. K1 statement and scope for exact and formal claims (invariant 14; reported by s3-domain)
Before: `k1_computational` checked neither `claim.statement` nor `scope.conditions`, so "this circuit will work when
built" was CERTIFIED-EXACT (verified on 4e676e9 for `lp` and for a circuit-shaped stub adapter,
`tests/test_kernel_scope_statement.py`, fail-first log `scratchpad/logs/s3k_ff_scope_alpha.log`).
Now (computational and formal classes): no scope conditions, and the statement must equal the adapter's
`scope_phrase` exactly; an adapter without one fails K1. `lp.scope_phrase` and `formal.scope_phrase` were added (their
hashes change again). The simulated class already had the rule. The data class has no scope vocabulary yet (its
statement stays free prose generated by the loop): stated, not changed. Museum: `SCOPE-STATEMENT`. The circuit adapter
on origin/s3-domain already exports `scope_phrase`, so it is covered once merged.

## 3. Claim bundles list large artifacts (GOAL L2)
`manifest["artifacts"]` (the run-bundle format, `store/run_bundle.check_artifacts`) lists every blob the certificate
needs: path `blobs/<sha256>`, bytes, sha256, kind (dataset / output / other), required, status `bundled` /
`available_locally` (over `bundle.LARGE_ARTIFACT_BYTES`, 64 MiB, UNCALIBRATED: listed, not zipped) / `referenced`
(missing or corrupted on the building machine; bytes -1). `reproduce_bundle(..., artifact_source=)` resolves a blob
the zip does not carry (hash-checked) and REPORTS every one it cannot find (`missing_artifacts` + a problem; the bundle
then does not reproduce). `chh reproduce` checks the artifact list first (fatal on a missing required artifact) and
looks in the local blob store and `--artifact-root` directories (files named by sha256).

## 4. CPU-time limits on Kernel-driven replays (GOAL §16.8)
`run_program(..., cpu_s=)` charges CPU time with a wall backstop of `CPU_WALL_BACKSTOP x cpu_s`. A backstop that
fires without a CPU overrun on a contended host, or with the contention witness unavailable, raises `InfraError`
(no certificate is issued; the caller retries): machine load is never a K3 verdict. On an idle host it is the
program's failure (it slept). K3 replays use the record's `cpu_s`, else its wall limit as CPU; held-out confirm runs
(`research/claims.py`) now run under, and record, `cpu_s` = the task's per-run limit. Test fakes whose `exec` lacked
the `cpu_s` keyword were updated (test_infra, test_research, test_run_revisions).

## 5. Non-interference replay as a K3 sub-check (§16.5.4, invariant 18)
Trusted host code declares agent-reachable copies of a target's truth (`Kernel.declare_truth_copy(target, dataset,
public file, column, declarer)`, ledger kind `truth_copy`). For every record K3 re-executes whose inputs hold a
declared copy, K3 runs `verify/noninterference.replay_noninterference` (flipped and constant worlds, decisions vs the
STORED production output; McNemar fallback for nondeterministic class programs) and fails closed on any change or
irregularity (`K3_NONINTERFERENCE`). Planted cases (`tests/test_kernel_noninterference.py`): a defeat device (cheats
only when the copy agrees with its own predictions) and a 2% stealth leak, both reading an ENCODED truth column that
K9's exact column scan misses, are rejected; the honest program certifies. Limits (stated): only DECLARED copies are
perturbed; copies the runner cannot place (e.g. baked into the image) are not tested; nobody in production declares
copies yet (task registration should, owner of research/suite.py).
