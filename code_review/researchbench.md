## 1. What the code actually does (architecture map)
Python CLI (`researchbench run-*`/`score-*`/`validate`) around three tasks with one OpenAI-compatible client (`clients.py`, temperature 0.0, no seed). Prompts are verbatim vendored from MOOSE-Chem (`vendor/moosechem_utils.py`, prompts.py:4; vendor file has `DISCIPLINE = "chemistry"` hardcoded and imports `google.genai`, so it is not usable as-is outside prompts). Data are JSONL: papers / retrieve / generation / ranking. The repo ships only 12 tiny tasks; full data is on HF.

Task formats (tiny split keys, verified):
- Retrieval record: research_question, background_survey, 75 `candidates` {title, abstract, label in gold/negative_t1/t2/t3}, gold_titles, discipline, doi.
- Generation record: research_question, background_survey, gold_inspirations (list), gold_hypothesis (`main_hypothesis`), fine_grained_hypothesis, experiments_details.
- Ranking record: research_question, gold_hypothesis, 5 `fake_negative_hypotheses` + 10 `model_negative_hypotheses` (15 negatives).
- Papers record has doi + discipline but NO publication date field (keys listed: abstract, background_survey, discipline, doi, experiments_details, fine_grained_hypothesis, inspirations, main_hypothesis, research_question, sample_id, source_index, title).

## 2. Core loop / scoring, step by step
- Retrieval (`retrieve.py:run_retrieve_record` ~lines 76-120): 75 candidates split into windows of 15; per window the LLM picks 3 titles; round 2 repeats on survivors. Titles fuzzy-matched back (`best_title_match`, threshold 0.62, retrieve.py:56). Score (`score_retrieve`, ~123-160): per-label hit ratio = selected/total per round, so gold hit ratio is a recall; negative-tier selection ratios measure distance-sensitivity. Note a round-2 "keep 3 of 75" is as described in README; pooled over samples via Counter totals (micro-average).
- Generation (`score_generation`, generation.py:622-664): LLM judge, temperature 0, scores 0-5 "matched score" vs gold hypothesis (`gold_key_points` if present else the whole gold hypothesis, :637); accuracy = mean/5. Judge model is the user's choice (`--judge-model`).
- Ranking (`ranking.py:run_ranking_record`, :55-85; `score_ranking` :88-162): for each of 15 negatives, compare gold vs negative in both orders; `rank = 16 - (#negatives preferred)`; `gold_wins = rank >= 9` (i.e. gold must beat at least 8 of 15 negatives). Position-bias stats: both-correct/both-wrong/self-contradictory pair ratios.

## 3. Paper/summary vs code discrepancies
- Dataset size: summary/paper v3 say 1,386 papers; release says 1,369 paper records / 1,367 retrieval / 1,367 generation / 1,323 ranking tasks (README:20). 17-paper gap unexplained.
- Ranking metric: the summary says "pairwise accuracy (% of correct rankings)" of gold vs 15 negatives; the code's headline `overall_accuracy` is the fraction of (sample, order) runs where gold ranks in the top 8 of 16 (`gold_wins = rank >= 9`, ranking.py:~80), a more lenient threshold than all-pairs accuracy. Pair-level ratios exist separately. Do not compare numbers across definitions.
- Unparsable ranking output defaults to `selection = 1` (ranking.py:~51), biasing toward candidate 1 and inflating position-bias metrics; paper-reported self-contradiction rates may be partly parser artifacts [inference].
- Summary says papers are "2024 onward". The tiny sample's DOIs encode 2022/2023 submissions (e.g. 10.1007/s00146-022-01415-0, 10.1007/s10311-023-01682-3, 10.1007/s00180-023-01376-y) — [inference] Springer DOI suffix year is submission year, so these may have been published 2023-2024; the record has no date field, so the "post-cutoff" claim cannot be checked from data. Also tiny sample 'Law' is s00787 (which I believe is a child psychiatry journal), 'Energy Science' s00170 (manufacturing) and 'Environmental Science' s00181 (economics) — [inference from journal codes, unverified] discipline labels look loose. Astronomy sample is a literature review article ("We have organized the review in two parts"), an odd "hypothesis" source. Chemistry and Material Science tiny records share one DOI, so records are not unique papers.
- Models: summary lists ~12 2025-era models; repo evaluates whatever the user gives. README shows score figures only as PNGs.

## 4. Mechanisms worth adopting — as a BENCHMARK for custom-harness (PLAN §10 axis E; §8.3)
1. **Axis-E sub-benchmark: Hypothesis ranking + inspiration retrieval (priority 1, effort S).** Both are fully automatic after dataset construction: retrieval scoring is string-match recall (no LLM), ranking is a parsed binary choice. These are cheap, deterministic (temp 0), and give tight CIs with ~1.3k tasks. Run them with (a) the bare frontier model and (b) custom-harness's critic/tournament modules (our K-way tournament and Bradley-Terry ranking in `verify/` are directly comparable with the ranking task: we could rank gold + 15 negatives jointly by BT instead of 15 pairwise calls, and report both). Layer: L3 eval adapter + L4 tournament reuse. Reimplement the loaders (50 LoC); code is MIT so copying `retrieve.py`/`ranking.py` scoring with attribution is allowed.
2. **Composition task (priority 2, effort S-M):** run gold-inspiration generation through our hypothesize/refine loop; the 0-5 LLM-judge match score is judge-dependent, so use a fixed, cross-family judge panel (PLAN §8.7) and report judge agreement; do not mix with other judges. Caveat: composing from gold inspirations is a closed-book rediscovery of an already-published idea, so contamination of the 2024+ papers into models released after 2024 is likely; use only models whose training cutoff predates the papers or mark contamination risk. We can pin a model cutoff only if the dataset has dates (it does not).
3. **Time-split rediscovery set (§8.3): partial reuse of the construction recipe only.** ResearchBench's tasks come with (research question, background, inspirations, gold hypothesis) extracted from a paper by an LLM agent with necessary/sufficient checkers (paper summary; builders.py not read). Our T4 needs: a task statement frozen at date T plus claims published AFTER T. ResearchBench provides neither: no dates, and the gold hypothesis is from the same paper that supplied the background (retrospective extraction, not forward prediction). Usable as: (a) an extraction template for our own pipeline (question/background/inspiration/hypothesis schema, 75-candidate pool with 3 tiers of citation-distance negatives, 15 negatives for ranking), (b) a candidate pool of 2024+ papers we could date via DOI/Crossref and rebuild post-T. The paper's ~82-92% extraction accuracy on 62 sampled papers (summary) means ~8-18% noisy gold; we need a human audit sample on whatever we derive.
4. **Dataset licensing consequence (important).** Data is CC BY-NC 4.0, includes publisher abstracts with upstream terms the user must satisfy, and the HF card says raw redistribution outside research groups is prohibited. custom-harness is a research project: eval-only use is fine; we must not bundle the data in our repo/releases, must not train/evolve prompts on it without noting NC terms, and must keep it out of any commercial path. Our own time-split set should be rebuilt from arXiv metadata under arXiv terms rather than copying their records. MIT code may be copied with attribution; the vendored MOOSE-Chem prompt file has no separate license notice in the file header I read [unverified; upstream MOOSE-Chem license not checked].
5. **Sealed-split rule:** the benchmark has no official train/test split that I saw (README/code). For our three-way splits (PLAN §10) we must define our own evolve/gate/sealed partition by DOI hash and never evolve on the sealed part.

## 5. Things custom-harness already does better
- Statistical reporting: ResearchBench prints point estimates (README sample output) with no CIs/seeds; we have paired-bootstrap CIs (STATUS L3).
- Position-bias: they run both orders; our Bradley-Terry ranking over multiple comparisons can be more efficient (inference).
- Judge governance: single user-selected judge, no agreement stats; we plan multi-family panels (PLAN §8.7).

## 6. Pitfalls / anti-patterns
- Fuzzy title matching with threshold 0.62 (`retrieve.py:56`, `best_title_match` in data_io.py not read) can credit near-duplicate titles; a model that outputs a long/garbled title may match wrongly [inference].
- Silent default `selection = 1` on parse failure (ranking.py ~51) and unknown-parse results excluded in generation scoring (`if score is None: continue`, generation.py:644-645): failures drop out of the denominator and inflate averages. Must count failures as 0 in our adapter.
- Judge sees `gold_key_points` if present else full gold hypothesis (generation.py:637); the full dataset's `gold_key_points` was not present in the tiny keys, so scoring falls back to whole-hypothesis matching, which rewards verbose outputs [inference].
- Single squashed commit; authorship ambiguity; dataset count mismatch with paper; literature-review papers and mislabeled disciplines in sample (§3).
- `vendor/moosechem_utils.py` imports google.genai and hardcodes DISCIPLINE="chemistry", so non-chemistry prompts mention chemistry [inference from vendor header + prompts.py `DISCIPLINE`; verify before running non-chemistry samples].

## 7. Verifier / evaluation / safety handling
No code execution at all; no sandbox needed. Verification: retrieval = exact-ish string recall vs labelled candidates (hard, T1-like); ranking = parsed binary choice vs known gold (hard but gold hypothesis is just "the published one", not necessarily better); composition = LLM judge (soft, T5-like). Anti-contamination = 2024+ publication claim only (unverifiable from data). `validate` CLI checks candidate counts, label coverage, empty fields, absolute paths, key leakage (README).

## 8. Bottom line
- Use ResearchBench ranking + retrieval as cheap, deterministic axis-E probes (eval-only; CC BY-NC data, MIT code); composition only with a fixed multi-family judge panel.
- Do not rely on it as the §8.3 time-split set: no dates, retrospective gold; borrow the schema and negative-sampling recipe and rebuild with dated, post-cutoff arXiv papers.
- Officialness ~65%: verify with authors before quoting as official numbers; paper/data count mismatch (1,386 vs 1,369) and ranking-metric definition differ from the summary.
