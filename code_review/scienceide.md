## 1. What the code actually does (architecture map)
Three layers:
1. **Environments** (`environments/<env>/`, 15 published): each = `source/` (pinned upstream tarball, sha256-checked), `cases/<check>/` (frozen inputs + `row.json` metadata incl. atol/rtol, timeout, reference-calibration data), `validation/<check>/{rubric.json,validate.py}` (the pass policy), `scoring/{grade.py,test.sh}` (reward ladder), `harbor/` (Dockerfile + instruction templates with `@PLACEHOLDERS@`, compiled per task), `authoring/{WRITER-BRIEF.md,harvest.json}` (task-writer brief per module; dead-code list, "pitfalls", noise floors; partly written in Chinese: environments/mitgcm-atmos/authoring/WRITER-BRIEF.md:1).
2. **Tasks** (`hard85/<env>/<task>/`): `task.toml` (taxonomy, difficulty facts, measured pass rates), `instruction.md`, `defect.json` (exact-edit {file, old, new}), `fix.json` (exact inverse), `authoring/provenance.json`, `eval/{evals.jsonl,summary.json}` (per-attempt model results). Two task modes seen: *repair* (inject a semantic defect) and *restore/excise* (delete a routine body, agent reimplements) (hard85/mitgcm-ocean/*excise*/instruction.md).
3. **RL glue** (`RL/scienceide_rl/`): not a trainer. It registers one PSRL agent loop (`ScienceIDEAgentLoop`, agent_loop.py:86-87) and one reward fn (reward.py:19) onto the external PSRL/veRL stack; episodes run via Harbor (`Job.create`, runner.py:269) with Harbor's `terminus-2` agent subclassed to truncate observations (agent.py:36-62).

Task compile is: sparse task (task.toml/instruction/defect/fix/provenance) -> `utils/harbor/to_harbor.py` (in the separate task-bank repo, NOT here; RL/scienceide_rl/prepare/README.md "1. Compile") -> Harbor dir with `environment/`, `tests/`, `solution/`.

## 2. Core loop, step by step (with citations)
**Episode** (runner.py `run_harbor_episode`, 132-327):
1. Build `JobConfig` with one task, one agent (terminus-2, temperature 1.0, `max_turns` required because stock terminus-2 defaults to 1,000,000 episodes: runner.py:161-163, 235), `override_timeout_sec=task_timeout_sec` (3600 s default, config.py:55) "so timed-out jobs remain gradable" (runner.py:218). Optional localization `hint` is delivered as Harbor `extra_instructions` (runner.py:258); editing the dataset `prompt` column does nothing (RL/README.md "Gotchas").
2. Agent works in container: edits `/app/MITgcm` (defective tree, no .git), builds with `rowtool.py`, runs rows, must leave `/logs/artifacts/<check>/` containing `_run_status.json` + final-iteration `.data/.meta` only (harbor/instruction-repair.md "Deliverable"; runtime_lib.py:242-283).
3. Separate verifier container (`[verifier] environment_mode="separate"`, `network_mode="no-network"`, 900 s; harbor/task.toml) runs `/tests/test.sh` -> `grade.py` against `/tests/reference` (scoring/test.sh:4-8).
4. If verifier did not run (agent raised), `_regrade_from_artifacts` regrades from the surviving artifacts with no agent (runner.py:64-129, 297-303); empty reward dict is kept distinct from a graded 0.0 (runner.py:78-80).
5. Reward -> `compute_score` returns `harbor_rewards[reward_key]` unchanged (reward.py:44-48); `reward_key` is per-task ("reward", or "reward_gpu" for GPU tasks: RL/tests/test_reward.py:24-37).
6. Termination classification: infrastructure failures (setup timeout, build failed, verifier timeout) are NOT policy failures (exceptions.py:77-88); empty-reward + exception => `VERIFIER_ERROR` so it "does not train as a real zero" (agent_loop.py:239-249). With `OVERLONG_FILTERING=True`, budget-truncated and ungraded episodes get zero loss mask but stay in the GRPO group baseline (RL/README.md "Metrics that matter"; implementation lives in PSRL, not read).
7. Container cleanup in `finally`, on a dedicated thread pool (runner.py:312-327).

**Reward ladder (mitgcm-atmos, scoring/grade.py)**: `score()` lines 91-110: crash/timeout/build_failed/missing/no_output/grader_exception = 0.0; structurally nonconforming = 0.1; conforming run = 0.2 (W_CONFORM); +0.5 only if EVERY pointwise-graded file passes (all-or-nothing "end-to-end object", comment lines 100-104); +0.3 if final iteration matches reference (W_TIME); full pass = exactly 1.0. Row rewards averaged over checks (grade.py:128). `reward_repair = max(0, reward - floor)/max(1e-6, 1-floor)` (grade.py:158-160), where `floor` is read from `/tests/floor.json`, measured at image-build time.
**Floor measurement** (verifier.Dockerfile stages `reference` and `straw`): build the clean pinned source and run each check -> `/ref`; copy tree, apply `defect.json`, build+run with timeout `@STRAW_TIMEOUT@`, grade through `grade_floor.py`; any build failure/crash/hang/missing output forces `floor = 0.0` (grade_floor.py:45-52); floor.json copied to the final verifier image. So an untouched repo scores reward_repair exactly 0.

## 3. Paper/summary vs code discrepancies
(Compared to autoresearch_survey/web_phai_scienceide.md and repo README.)
- Summary: "27 codebases, 64 environments, 2,812 tasks, 1,076 executable checks". Repo ships 15 envs and 30/85 hard tasks; the factory/pipeline is in another repo (README "What is in this repository"). Counts not verifiable here. I did count 244 rubric.json files across the 15 published envs.
- Summary: "Pointwise vs invariant policies". True in code, but the split is lopsided: 199 `pointwise` + 24 other pointwise variants vs only **12 `invariants`** rubrics (grep over environments/*/validation/*/rubric.json); only 4 flagged `chaotic: true`. Invariants are statistical-agreement checks (see §7), not physics laws like energy conservation as the summary implies. The "drift" mode (conserved quantity must stay within `max_relative_drift`) exists in validate.py:82-93 but I found no evidence of how many rubrics use it (not counted).
- Summary: "Tolerances locked before task generation". Plausible; rubric.json `evidence`/`warrant` fields record calibration, but the locking step is in ScienceInfra (not read).
- Summary/README: "verifier recompiles the code". **For mitgcm-atmos the verifier does not recompile the agent's source.** The agent builds and runs inside its own container and delivers *output files* in `/logs/artifacts`; the verifier only validates those files against `/tests/reference` (scoring/test.sh; grade.py `grade_check`). Stim uses the same artifact-delivery pattern (stim-stab/scoring/grade.py:15-23, requires `run.ok`). Reward is therefore earned by delivered outputs, with "do not fabricate/post-process" enforced only by instruction text (harbor/instruction-repair.md "Deliverable") plus the fact that reference output is absent. [inference] this is weaker than "verifier rebuilds the patched tree"; hard-coding a source-side special case that reproduces the correct output is not detectable by this verifier. I did not read the other 13 envs' graders.
- Summary: "Asymmetric PPO / group size 8 / ε 0.2-0.3". RL/README.md says async GRPO on PSRL; PPO clip params and group size live in `scripts/fsdp_qwen35_4b.sh` (not read). Not verified.
- Summary: "1-hour budget" -> code: `task_timeout_sec=3600` (config.py:55). Matches.
- RL/README.md says 5 environments ship in the task bank incl. LAPS; **LAPS is held out** in this repo (README "Held out" list), so the headline RL results (laps, mitgcm-biogeo curves) cannot be reproduced from this repo alone. ## 4. Mechanisms worth adopting into custom-harness (ranked by expected value)
Our current state: `verify/metrics.py` (4 trusted metrics), `research/task.py` (private test_y never in agent workspace), tiers T0-T6 (`tiers.py`), seed bootstrap CIs. No verifier mutation-testing, no exploit quarantine, no floor/normalized reward, no calibrated tolerance process (STATUS.md "Next" item 4).

1. **Verifier mutation-testing evidence baked into each verifier (rubric `evidence.faults`)** — held-suarez-cs/rubric.json `evidence`: nominal-vs-variant spread, altbuild floor, and named fault injections ("cheaper_solver": cg2dTargetResidual->1e-3 gives bound_fraction 6.7e6, FAIL; "wrong_coefficient" x1.05 gives FAIL), recorded with date, host, and exact command. Better than ours: PLAN §3/L3 promises mutation testing but code has none (`verify/` has only metrics/ranking/stats). Layer L3 (verifier registry `validated_by`). Effort S-M (data schema + harness to run known-wrong candidates). Reimplement (no license on ScienceIDE code; ideas only).
2. **Calibrated-tolerance protocol: tolerance = f(measured legitimate-variation spread)**. Pointwise: nominal vs `variant` (2-ulp parameter perturbation) vs `altbuild` (strict-IEEE -O0 build) spread defines the noise floor; bound must sit above it and below fault signals ("marginal = symptom smaller than tolerance, funnel kills it", WRITER-BRIEF.md:23-25). Statistical invariants: bound = 5·sqrt(2)·sd of pairwise spread across 12 independent seeds, rounded up to {1,2,2.5,4,5}×10^k, and max'd with the analytic sampling error because a 4-seed sd under-estimated by 2.5x (stim-stab/validation/detection-event-sampling/rubric.json `evidence.spread_how`). Directly applicable to our ML tasks: define "beats baseline" thresholds from seed variance of baseline and of an equal-compute re-run, not a fixed delta. Complements our T2 bootstrap (`verify/stats.py`). L3. Effort M. Reimplement.
3. **Floor-normalized reward + zero-for-untouched** (`reward_repair = max(0, r-floor)/(1-floor)`, grade.py:158-160; floor measured by actually running the broken artifact, grade_floor.py:45-52). For our ML tasks: floor = baseline.py score; reward = normalized improvement. We already have baseline.py (`research/task.py`) but do not normalize. L3/L8. Effort S. Reimplement.
4. **Graded partial-credit ladder with all-or-nothing core** (0 crash / 0.1 malformed / 0.2 conforming / +0.5 full state / +0.3 timing; grade.py:91-110) and measured evidence that it is climbable: unhinted/early runs were bimodal {0, floor}, after hardening 23/144 trials landed between 0 and floor and 9 above (RL/scienceide_rl/eval/FINDINGS.md "reward distribution"). Lesson: design the ladder so intermediate behaviours (valid submission format, runs, correct shape) are rewarded but the "bag of independently useful sub-scores" is not (comment grade.py:100-104). L3, effort S. Reimplement.
5. **Validity gates before a task is admitted**: oracle must score ~1.0 ("the oracle step is not optional", RL/README.md Quickstart), nop agent proves infra, unfixed build must leave room (floor <= 0.65 per hard85 provenance `thresholds.FLOOR_MAX`), symptom must exceed tolerance (`MARGIN_MIN` 1e-13), exact-edit invertibility (apply_defect.py:15-20 asserts `old` occurs exactly once; fix.json is exact inverse). Map to our task-suite builder: every ML task must ship an oracle solution that scores max, a nop/baseline that scores floor, and a mutation set. L3/L4 task-suite builder (STATUS "Next" #2). Effort M. Reimplement.
6. **Leak hygiene for agent image** (anti-reward-hacking, see §7): multi-stage Docker builds where archive+defect only exist in a `prep` stage (stim-stab/harbor/agent.Dockerfile), `strip-tree.py` removing upstream tests/backup/variant copies (strip-tree.py:12-28), no `.git` (verifier.Dockerfile `test ! -e /opt/MITgcm/.git`), canary GUID in every task file and instruction (task.toml `canary`, `<!-- @CANARY@ -->`), network allowlist limited to model endpoints, `leak_audit` regex over session logs for git clone/curl/wget of upstream (evals.jsonl `leak_audit.upstream_fetch_actions`). Adopt: canary strings in all task assets + post-hoc leak audit over traces in `store/evidence`. L0 sandbox + L3. Effort S. Reimplement.
7. **Infra-vs-policy failure taxonomy for training signal** (exceptions.py:77-102, agent_loop.py:239-249, runner.py `regrade`): a missing verifier score is "ungraded", never 0. For us: our `records`/evidence should have an explicit `ungraded` state excluded from evolve gate statistics (L6 `evolve/selection.py`). L6/L8. Effort S.
8. **Hint ladder for difficulty control** (L1 file+line, L2 file, L3 none; prepare/README.md §3) justified by "unhinted 4B scored near zero". Useful for curriculum in our task suite and for ablating localization vs repair ability. L8/task-suite. Effort S.
9. **Measured difficulty, not labels**: `[metadata.difficulty_facts]` carries `measured_pass_rates` per model, k edit sites, verification cost, `near_duplicate_cluster`, `instruction_disclosure` (hard85/.../task.toml); `difficulty = "unrated"` with `legacy_*` labels retained. Adopt for our task registry. Effort S.

## 5. Things custom-harness already does better (with evidence)
- Private labels are structurally separated from the agent workspace and verified by a host-side trusted metric implementation (`research/task.py` docstring; `verify/metrics.py` "run on the host, never by agent code"). ScienceIDE's agent sees the full `rubric.json` and `validate.py` (`/app/checks/<check>/`, instruction-repair.md "Available in the container"); only reference outputs are hidden. Our hidden-test design hides the evaluator inputs.
- Statistical rigor on comparisons: paired bootstrap, seed bootstrap (`verify/stats.py`), gate split with CIs in evolve. ScienceIDE reports means over small n (hard85 pass rates like [3,3], [1,1], [0,3]; FINDINGS "7 vs 9" solves) with no CIs and notes its own moved-three-variables confound (FINDINGS "Caveat").
- Tier policy attached to every claim/object (PLAN §3-5); ScienceIDE has one scalar reward key.
- No dependence on a heavy external stack; ScienceIDE needs Harbor + PSRL + veRL + Ray + Docker-per-episode with fuse-overlayfs image accumulation issues (RL/README.md Gotchas).
- Evolvable harness spec with static checks; ScienceIDE trains weights only, with no scaffold self-improvement (RL README; agent harness is stock terminus-2 with one subclass).

## 6. Pitfalls, bugs, or anti-patterns seen (we must avoid)
- **Output-delivery grading without source rebuild** (see §3): agent self-reports artifacts; mitigations are textual. For our ML tasks keep running the agent's code under the *trusted* sandbox with hidden data (we do), never accept self-produced predictions on public test.
- **Agent can read the grader**: `/app/checks/<check>/{validate.py,rubric.json}` ships in the agent image. Safe only because reference outputs are hidden; for invariant checks computed from a *reference summary statistic*, agent knowing the bound is harmless but any embedded expected value would leak. [inference] Watch for expected values in rubric.json.
- **Wall-clock-dependent grading**: the verifier's 120 s reference-run cap makes ~3 s simulations time out under concurrency, "top source of wasted episodes" (RL/README.md Gotchas). Row `timeout` is also part of status->0 mapping (grade.py:91-95). Our budget/time-limits must separate infra timeouts from candidate timeouts.
- **Zero-variance and bimodal rewards**: early runs scored only {0, 0.5}; delivery rate 2% (FINDINGS). Don't launch RL/evolution before checking the reward histogram.
- **Budget-as-slack bug class**: `max_model_len` forwarded as `max_input_tokens` so agent spends all of it; they subtract an 8192 margin (runner.py:34-36, 237-245) and note raising it back causes length overflow. Related: `TruncatingTerminus2` exists because Harbor hard-codes a 10,000-byte observation cap (agent.py:1-9).
- **Sloppy temp handling**: `tempfile.mktemp` (race-prone, deprecated) for compose override (runner.py:201). Minor.
- **Instruction-text honesty clauses are the only guard against hard-coding** ("Do not hard-code outputs, dimensions, iteration counts, or this deck's values", instruction-repair.md). A model that fits the deck's constants would pass pointwise-on-one-deck checks when the defect is a data constant (e.g. hard85 `sem-data-aim-convection-qbl`: QBL 14->15 is a *single literal*, found by tuning/search instead of understanding; `literal_defect = true`). [inference] "Hard" tasks of this family reward numerical guess-and-check against only the visible run; the verifier cannot tell a derived fix from a fitted one unless the fitted value is wrong elsewhere (single check in this task: `checks_count = 1`).
- **Per-env copy-paste**: 15 near-identical grade.py/grade_floor.py/rowtool variants (diff of mitgcm-atmos vs stim-stab grade.py differs substantively only in the check list/validator invocation) => drift risk; their own gotcha "fix belongs in envs/<env>/env/harbor/" (prepare/README.md).
- **No license on their code**: cannot copy.
- Mixed-language authoring artefacts (Chinese strings in WRITER-BRIEF.md) and absolute `task_path` baked into parquet (RL/README.md Gotchas) = brittle pipeline.
- Test results are n=1-6 per model per task (hard85 `measured_pass_rates`); not statistically meaningful per task.

## 7. Verifier / evaluation / safety handling
**Pass policies** (validation/<check>/validate.py + rubric.json; 244 rubrics: 199 `pointwise`, 16 `pointwise-final-evolution-frames`, 8 `pointwise-end-to-end`, 12 `invariants`; 207 `chaotic:false`, 4 `chaotic:true`):
- *Pointwise* (mitgcm-atmos/validation/held-suarez-cs/validate.py:98-131): every graded final-state value must satisfy |c-r| <= atol + rtol|r| (atol 1e-10, rtol 1e-8 in rubric), reference-defined file set, same final iteration, shape match, **non-finite values fail** (line 116), `not_graded` fields and records are excluded explicitly; required fields enforced. Chaos is avoided by design: runs are shortened to the deck's own few-step window so trajectories cannot separate ("short enough that the chaotic dry core has not yet separated", rubric `configuration`); `chaotic:true` rubrics exist for the 4 where this is not possible.
- *Invariants* (stim-stab/validation/detection-event-sampling/validate.py:28-93): modes `agreement` (a statistic {final,mean,max,min} of a column must agree within atol+rtol|ref|) and `drift` (quantity conserved within each run, max relative drift <= bound). For stochastic sims the six invariants are mean/max/min flip rate, spread, per-shot dispersion and any-event fraction, each with its own bound (rubric `comparison.invariants`). Reports `bound_fraction` = largest fraction of its bound used (headroom measure).
- Grader runs as an isolated subprocess: `python -B -s -E`, env scrubbed to PATH+LANG, scratch tempdir (grade.py:56-63; stim grade.py:24-33). Validator crash/exception => `grader_exception` => 0.0 (grade.py:65-69) — fail-closed.
- Fault-sensitivity evidence per check (see §4.1); calibrated floor via altbuild.

**Anti-reward-hacking measures actually present in code**: (a) separate verifier container with no network, grading artifacts against reference+checks copied only into the verifier image (task.toml `[verifier]`, verifier.Dockerfile final stage); (b) agent image excludes archive, defect record, reference, .git (verifier.Dockerfile test, agent.Dockerfile prep stage, strip-tree.py); (c) agent network allowlist = LLM endpoints only (task.toml `[agent] allowed_hosts` has no github.com, unlike `[environment] allowed_hosts` which includes github.com/pypi for build); (d) canary GUID in every file + leak audit regex over sessions (evals.jsonl); (e) unfixed repo scores exactly 0 via floor normalization; (f) all-or-nothing final-state credit so "unrelated field unchanged" does not earn most of the reward (grade.py:100-104); (g) crash/hang/missing output mapped to 0 (grade_floor.py); (h) oracle validation + hint-free control; (i) reward only from verifier in training; policy never sees reward key (reward.py).
**Not present / not found**: hidden invariants (agent sees every validator and rubric); randomized/perturbed re-evaluation (quarantine); tamper detection of delivered artifacts (e.g. hash of agent-run binary vs submitted source); source-diff constraints (e.g. "only these files may change", "no edits to rowtool/cases"). Only instruction says "do not modify checks, validators, inputs, build helper" (stim instruction-repair.md). I found no code enforcing that; since `/app/checks` is not the graded copy, tampering with it cannot change the score, but tampering with `/app/cases` inputs or `rowtool.py` could change the delivered artifacts — [inference] unmitigated except by the reference comparison.
**Sandbox**: Docker per episode (compose project per session, labels psrl.actor_id, `mem_limit` override, optional GPU override: runner.py:184-206); Harbor-enforced agent timeout; `finally`-cleanup incl. dangling image prune (runner.py:312-327). No gVisor/seccomp configured in repo. Per-task `cpus=4, memory_mb=8192`.

**Reusability as custom-harness research tasks**: 
- Direct reuse of ScienceIDE tasks as custom-harness *ML research tasks*: **No.** They are Fortran/C++/Julia scientific-code *repair/restore* tasks requiring Harbor + gfortran/CMake builds (hard85 task instructions; verifier.Dockerfile), format = "find injected defect in a 30k-line source tree", not "improve a metric on a fixed dataset" (our TaskSpec in research/task.py). Plus: no license on task metadata, so copying is not allowed (only the published upstream-code licenses are known).
- Best-fit candidates *if* we later add a "scientific-code repair" benchmark axis (PLAN E1 already lists "ScienceIDE envs"): (1) the **Python-based envs**: `dscribe-descriptors` (Apache-2.0; ~hundreds of rows e.g. coulomb/ewald/ACSF descriptor checks), `stim-stab` (C++/Python bindings; Apache-2.0; 3-minute builds), `edkit` is Julia; (2) the cheap MITgcm atmos decks (3 s runs) but 8 min Docker build each (RL/README.md "Evaluate"). None need GPUs except a few ("`--skip-gpu-tasks`").
- Task *format* is reusable idea-wise for our suite: {sparse source + exact-edit defect/fix pair, symptom-only instruction, public rubric + hidden reference outputs, floor/oracle gates, measured difficulty}. We can implement an "ML-pipeline repair" family in our own format: take a known-good sklearn/torch training script, inject an exact-edit bug (label leakage fix reverted, wrong normalisation, off-by-one in split), reward = normalized improvement over the buggy baseline measured on hidden test_y, with oracle = inverse edit. This gives automatic floor/oracle/mutation machinery cheaply.
- hard85 evals.jsonl contain real model results (opus, sonnet, haiku, kimi etc.) — usable as *calibration data* of difficulty, not as tasks.

## 8. Bottom line
- Real value is the **verifier-engineering recipe**, not the code: calibrated tolerances from measured spreads (nominal/variant/altbuild; 5σ-rounded for stochastic invariants), fault-injection evidence per verifier, oracle+nop+floor gates, floor-normalized partial-credit ladder, leak hygiene (canary, stripped trees, no-network verifier). Adopt into L3 and the task-suite builder; reimplement (no license).
- Their weakest point for our L3 goals: validators are fully public to the agent, there are no hidden invariants, no quarantine, and grading is of delivered artifacts rather than a rebuild; custom-harness's hidden-test design is stronger there.
- Public repo is a preview: factory/pipeline/validity-gate code is not included (ScienceInfra), so claims about task-generation quality cannot be verified from code.
- Tasks themselves are not directly reusable as our ML research tasks (wrong domain/format, heavy Docker builds, no license on metadata); borrow the task format and build an ML-pipeline-repair family.
