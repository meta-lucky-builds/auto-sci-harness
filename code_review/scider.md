## 1. What the code actually does (architecture map)
SciDER is a **prompt-driven LLM agent system built on a Claude-Code-style tool loop**, not a pipeline of computed artifacts. Each "agent" (`scider/agents/{data,ideation,experiment,critic,approval,coding_subagent_*,paper_subagent,writing}_agent`) is a single `query(...)` tool-use loop (`data_agent/execute.py:79-106`, `ideation_agent/execute.py:44-68`, `experiment_agent/execute.py:105-129`) with a role-specific system prompt in `scider/prompts/*.yaml`, a tool whitelist (`AGENT_TOOLS`), and a LangGraph-style `build.py` graph. Workflows in `scider/workflows/` chain agents: `full_workflow.py` (Data -> Experiment -> optional Writing; `FullWorkflow.run` at L115, phases L144/L194/L234) and `full_workflow_with_ideation.py` (Ideation -> Data -> Experiment -> Writing).

The only substantial *algorithmic* (non-prompt) code that implements a paper mechanism is the evolutionary idea search (`idea_search.py`). Everything else the paper presents as formal machinery (typed data report R with dependency graph, static guard g(C), runtime monitoring at 30 s, per-axis confidence sigma, headless approval) is either a prompt instruction or absent (see section 3).

Other components: skill system with lazy loading (`core/skills.py`, SKILL.md frontmatter `allowed_agents`/`preload_for`; ~30 skills under `.scider/skills/`), plan mode, memory, history compaction (`core/compact.py`, 537 L), permission system (`core/permissions.py`), LLM role registry (`core/llms.py`, `model_settings/`), per-benchmark wrappers (`bench_workflows/`), SFT pipeline (`train/`, `data_generation/`).

## 2. Core loop, step by step (with file:line citations)

### 2a. Data profiling (what is really computed)
1. Data agent is mandated by prompt to run `eda_analyzer.py` on every file with an output path, then `Read` the markdown report back (`prompts/data_agent_prompt.yaml:12-34`). It then writes a summary that must quote numbers (`:91-107`). Output is free-text markdown (`DataAgentState.output_summary`, `data_agent/execute.py:109-140`).
2. `.scider/skills/exploratory-data-analysis/scripts/eda_analyzer.py` (548 L) is extension-dispatch. For CSV/TSV (`:269-283`) it computes, **on only the first 10,000 rows** (`nrows=10000`): `shape`, `columns`, `dtypes`, `isnull().sum()`, `df.describe()`. That is all. For `.npy`: shape/dtype/min/max/mean/std. For JSON: top-level type/keys/length. For HDF5: group/dataset tree with shapes/dtypes. Bioinformatics/imaging branches exist (`analyze_bioinformatics` L330, `analyze_imaging` L380; not read in detail). Other categories (chemistry, spectroscopy, proteomics) fall into `detect_file_type` + a reference-doc lookup only; `analyze_file` (L208-237) has no analyzer for them ("Add more specific analyzers as needed" comment at L233).
3. Domain-specific `*_profiler.py` scripts exist (`chem_profiler.py` 254 L, `text_profiler.py` 411 L, `ts_profiler.py` 241 L, `physics_eda.py`); they are skills the agent may choose to invoke. I only counted their lines; did not read them.
4. Grep over `scider/` for "z-score", "foreign key", "value-set", "file tree", "dependency graph", "semantic role", "role bind" returned **no matches** in code or prompts. The only trace of a relationship analysis is one sentence in the prompt: "Relationships: File dependencies, join keys, temporal ordering, cross-references, directory structure" (`data_agent_prompt.yaml:61`).

### 2b. Ideation and K-way ranking (`idea_search.py`)
1. Seed ideas come from an LLM agent loop (web search + paper-search subagent) that writes a free-text report; a second LLM call extracts a JSON array (`ideation_agent/execute.py:104-169`). The ideation prompt asks the LLM to self-assign a 0-10 novelty score (`prompts/ideation_agent_prompt.yaml` step 5).
2. Constants: `POPULATION_SIZE=8`, `MAX_ITERATIONS=3`, `MAX_LLM_CALLS=60`, `SURVIVORS_PER_ITER=4`, `IMPROVE_FRACTION=0.75`; weights novelty .30/feasibility .25/impact .25/specificity .20 (`idea_search.py:50-62`).
3. **Scoring** `_score_dimension` (`:193-245`): one LLM call per dimension, `temperature=0.2`, prompt lists **all n ideas in population order** (`_ranking_prompt` `:166-190`) and asks for a permutation. Validation: permutation check (`:216`). Normalized score `(n+1-rank)/n` (`:220`). On any failure every node gets neutral 0.5, overwriting prior scores (`:236-245`). Four dimension calls per pass, run in a thread pool (`score_population` `:260-296`). Composite = weighted sum (`:248-257`).
4. **Loop** `run_idea_search` (`:445-656`): score seeds (4 calls) -> pin best seed (`:511`) -> for up to 3 iterations: survivors = pinned seed + top-3 others (`:537`); n_new = 8 - 4 = 4; n_improve = round(4*0.75)=3, n_combine = 1 (`:539-541`); Improve targets the parent's lowest-ranked dimension with a dimension-specific instruction (`:71-92`, `:551-566`, parent chosen round-robin `i % len(survivors)`); Combine samples two survivors by rank-proportional weights (`_rank_proportional_sample` `:418-442`) and passes each parent's "top rationale" (`:568-589`); then **re-scores survivors + new nodes together** (`:595-601`, +4 calls). Final authoritative pass re-scores the whole final population (`:611-616`). Budget: reserves 4 calls for the final pass when `max_llm_calls >= 16` (`:525`). Arithmetic: 4 (seed) + 3 x (3+1+4) + 4 = 32 calls for the defaults; the 60-call cap is therefore not binding with defaults [inference from the constants].
5. Result: `best_ideas` sorted by composite; the rank-normalized mean is a constant so they report **best composite** as `idea_score` (`ideation_agent/execute.py:201-206`).
6. Idea selection for experiments is by the **user** (`selected_idea_index`) or, absent that, the experiment agent receives the whole ideation report and "asks the user which one to implement via AskUserQuestion" (`full_workflow_with_ideation.py` `_run_experiment_phase`, ~L318-330). In headless mode I did not verify what happens (did not read `AskUserQuestion` auto-mode; `tests/ask_user_auto_mode_test.py` exists).

### 2c. Research pipeline order
`FullWorkflowWithIdeation.run` (`full_workflow_with_ideation.py:~L146-173`): **Ideation (1) -> Data (2) -> Experiment (3) -> Writing (4)**. The Data phase receives the ideation summary ("Prior Ideation Results... Do NOT search for papers again", `:~L228-236`); ideation never receives the data report (grep for `data_analysis|data_desc|data_summary` in `agents/ideation_agent/*` and `workflows/ideation_workflow.py` found nothing). `FullWorkflow` (no ideation) is Data -> Experiment -> Writing.

### 2d. Experiment agent
Prompt-driven: EnterPlanMode -> TodoWrite -> delegate coding to a `coding` subagent (native or Claude SDK, selected by env `CODING_AGENT_VERSION`, `experiment_agent/execute.py:46-50`) -> run code with Bash itself (background tasks up to 12 h) -> verify -> report (`experiment_agent_prompt.yaml:14-60`). Mandated "ml-model-evaluation" rules: compare to trivial baseline, no train-set eval, report uncertainty (`:124-130`). Summary step has a degenerate-summary detector + one forced retry (`execute.py:132-155`, `:158-218`).

### 2e. Critic / approval
`critic_review_node` (`critic_review.py:23-96`) runs a read-only critic loop over the last 20 messages; `_extract_verdict` (`:218-241`) is **keyword matching**: looks near "overall assessment" for "strong"/"adequate"/"good" -> pass, "poor"/"needs improvement" -> retry; else "critical" + "issue|error" anywhere -> retry; default pass. `user_review_node` auto-approves when no feedback or `critic_retry_count >= max_critic_retries` (default 2) (`:112-115`). In headless mode a separate approval LLM subagent with read-only tools returns `{"verdict": approve|reject}`; its prompt says "When in doubt ... APPROVE" (`approval_subagent_prompt.yaml` section 5).

## 4. Mechanisms worth adopting into custom-harness (ranked by expected value)

1. **Tiered "mandatory deterministic profiler first, LLM reads the report" pattern, but done properly** — what SciDER shows is the *value* of forcing the profile step (prompt hard rules `data_agent_prompt.yaml:15-34`); what it actually computes is thin (D1/D2). Our `research/data.py:63-99` is already deterministic and *better in two respects* (see section 5), so the adoption is the **missing components**, not SciDER's code: (a) outlier counts per numeric column (z-score or IQR), (b) cardinality/duplicate-row rate, (c) cross-table key/value-overlap graph when a task has >1 file, (d) semantic role candidates (target/time/id/group) from deterministic heuristics, (e) constraint violations (negatives in count columns, dates out of order). Layer L4.2; effort S-M; **reimplement** (their code does not contain these; Apache-2.0 would allow copying the 10k-row `describe` snippet, which is trivial). Falsification: PLAN section 8.14 test (infeasible-hypothesis rate with vs. without) — SciDER's own claimed gains (+0.238 / +0.153 on two DiscoveryBench families per the summary) are from an LLM-agent loop and are not reproduced by this repo's code.
2. **Evolutionary idea operators with dimension-targeted improvement and rationale-carrying crossover** (`idea_search.py:71-92, 323-411, 418-442`). Compared with ours: `research.tournament` (`modules.py:118-158`) only *ranks* a fixed hypothesis list; it never mutates. Improve-along-weakest-dimension and Combine-with-"strongest aspect"-rationale are cheap and give a generate-rank-refine loop with a budget. Add as an optional L4.4/L4.5 loop around our tournament, **using our BT ratings instead of their per-call rank normalization** (their composite is not comparable across batches, acknowledged at `:272-275`). Effort M; reimplement (Apache-2.0 allows copying; the prompts are generic). Caveat: their only evidence for benefit is a same-family LLM judge on seeded toy ideas (D13); for us the gate should be T1/T2 downstream metric on the data task, not LLM judge.
3. **Pin-the-best-seed anti-displacement + final authoritative re-score on a level field** (`:506-511, 606-616`). Cheap guard against a high-quality seed being evicted because of batch-dependent ranks. With our Bradley-Terry across rounds it is less necessary, but "carry the incumbent into every comparison" is a good rule for L6 edit tournaments too. Effort S; reimplement.
4. **Reserved-budget accounting for the final scoring pass** (`:520-525`): reserve calls so the lift metric is always measurable. Fits L1 budget ledger. Effort S; reimplement.
5. **Trajectory export schema** worth borrowing for L8 data (`history_export.py:60-125`, `train/dataset/README.md`): one JSONL row per agent/subagent trajectory with `id=<workspace>/<agent>/<traj>`, role-tagged messages, `tool_calls`, restored pre-compaction tool outputs (`_restore_original_content` `:41-57`), `reasoning_content` kept as a separate field, compaction boundary markers. Preprocess steps (`train/README.md` section 2b): merge consecutive same-role turns, head/tail-truncate tool output to 512 tokens, split at user-turn boundaries at 16k tokens, drop orphan tool calls, enforce strict user/tool<->assistant alternation, `--minimal` to `{id, messages, datasource}`; LlamaFactory `formatting: openai`. For us this is a ready recipe; **the part to add that they lack is outcome/verifier tagging and backend/ToS tagging per row** (PLAN section 14.3, 8.8). Layer L8; effort S-M; reimplement the format (Apache-2.0, copying `preprocess_data.py` logic is allowed with attribution).
6. **Degenerate-output detector with one forced retry** for report/summary steps (`experiment_agent/execute.py:132-155`): length + header + deferral-phrase heuristics. Maps onto our contract-with-bounded-retries (`runtime/`). Effort S; reimplement.
7. **Skill descriptor lazy loading** (`core/skills.py`): L5 skill library injecting only name+description by default. Effort S-M; low priority and unmeasured by them.
8. **Benchmark-wrapper practice of inlining grader/leaderboard info into the prompt** (`bench_workflows/mlebench_workflow.py` header): this is a *warning*, not an adopt item (see section 6).

## 5. Things custom-harness already does better (with evidence)
- **Deterministic, host-side profiling that is not an LLM loop**: `research/data.py:63-99` is pure code over the whole train CSV (not the first 10k rows), gives per-column type/missing/min/max/mean/std/n_unique/top-5, target task-type inference and class counts, ID-column and high-missingness flags. SciDER's profile is LLM-mediated, truncated to 10k rows (`eda_analyzer.py:270`), and its report is whatever the LLM paraphrases.
- **Private-label discipline**: our `dev_split` holds labels on the host (`data.py:38-52`, `modules.py` setup stores `_private_dev_labels_ref`; STATUS: `_private*` never renders into prompts). SciDER instead *hands the MLE-Bench grader source and leaderboard thresholds to the agent* (see section 6).
- **K-way ranking robustness**: ours shuffles presentation order per round with a seeded RNG, runs multiple rounds, discards non-permutations instead of guessing, and aggregates with Bradley-Terry with a prior (`modules.py:118-158`, `verify/ranking.py`). SciDER: single unshuffled pass at temp 0.2, silent 0.5 fill on failure, composite from batch-local ranks (`idea_search.py:193-245`). Ours also reports `rejected_rounds`.
- **Tournament input includes the data profile and baseline metric** (`modules.py:131-138`: `Data profile: {...}`), i.e. ranking is conditioned on data feasibility; SciDER's ranker prompt has only topic + idea text (`:166-190`).
- **Deterministic acceptance**: hidden-test verification and tier policy are code (STATUS L3/L4); SciDER's gating is LLM judges with keyword verdict parsing and "when in doubt approve" (`critic_review.py:218-241`, `approval_subagent_prompt.yaml` s5).
- **Sandboxing**: ours is Docker no-network non-root (STATUS L0); SciDER's execution is local-process in a uv workspace with a regex blocklist classifier (`code_env.py:60-100`, `run_bash_cmd/__init__.py:103-190`, `permissions.py` default ALLOW "no user to ask" L8-17). Their Dockerfile exists for the whole app, not per-run isolation (not read beyond header).
- **Evidence/claims/audit, statistics, evolution/gate**: no counterpart in SciDER (no CI, no seeds protocol enforced in code, only prompt rules `experiment_agent_prompt.yaml:124-130`).

## 6. Pitfalls, bugs, or anti-patterns seen in their code (must avoid)
1. **Paper claims machinery the code does not contain** (D1, D2, D6, D7, D8). Lesson for our README/papers: every mechanism claim needs a code pointer and a test; add this to our review checklist.
2. **Keyword-based verdict parsing**: `"good" in window` makes "not good" or "no good evidence" pass; default is `pass` on ambiguity (`critic_review.py:228-241`). Our verdicts must be structured JSON + schema, never substring.
3. **Approval gate biased to approve** ("When in doubt ... APPROVE", `approval_subagent_prompt.yaml` s5) and auto-approve at retry cap (`critic_review.py:113-115`). Gate strength is below what the paper's "mitigating LLM-judge instability" implies.
4. **Score fill-in of 0.5 on failure mixes scales** silently (`idea_search.py:236-245`), and the final selection is by batch-relative composite, so "best composite" is *by construction* high for whichever idea the same LLM ranks first in the last batch; the "lift" metric (`evals/eval_idea_search.py:445, 573`) compares the same LLM's ranking before/after search, i.e. self-referential. Also the in-loop ranker and the improve/combine generators are the same model family (self-preference) [inference].
5. **Position bias unmitigated** (no shuffle, children appended last, `:604`).
6. **Grader leakage by design in the MLE-Bench wrapper**: preamble "inlines the grader source, Kaggle leaderboard thresholds" (`bench_workflows/mlebench_workflow.py:10-14, 200-206`). This is legal for benchmark runs but means reported MLE-Bench medals are with grader visibility; our scorecard (PLAN section 10) must forbid it. [I did not read whether the preamble is *used* for the paper's numbers; it is the default path.]
7. **Train/test contamination for the open model**: SFT generation is run on the AI-Idea-Bench `test` split with a comment denying contamination (`data_generation/aiidea/generation.py:45-48`), while the paper evaluates OpenSciDER on AI-Idea-Bench. Same pattern for other benchmark-derived SFT sets (DSBench, ScienceAgentBench, DataSciBench are also benchmark task sources, `data_generation/README.md` table) — check disjointness before comparing with their numbers.
8. **Unfiltered SFT** ("we do not filter trajectories", incl. failed ones, `data_generation/README.md`) while the paper credits the SFT set for the novelty jump (63.22 vs 47.53 closed-source SciDER, per summary). Without outcome labels this is either distilling the teacher's *style* or learning to game an LLM judge; we need doubly-verified trajectories (PLAN 8.8).
9. **Truncating tool output to 512 tokens in SFT data** (`train/README.md` 2b) trains the model to act on heads/tails of outputs it will see in full at inference [inference]; fine as a throughput hack, risky as a default.
10. **Permissive local execution**: `permissions.py` default ALLOW; blocklist classification (`run_bash_cmd/__init__.py:103-190`) is bypassable by design (regex on command names/patterns). Do not copy.
11. **Model-identity inconsistency across the repo** (Qwen3.5-9B in `train/README.md`, Qwen3.6-27B in `data_generation/*/roles.yaml`, "27B" in the summary): reproduction would require clarifying which checkpoint produced the numbers.
12. **Unmeasured cost**: no cost/latency logging beyond token counters on emitted messages (`idea_search.py:27-40`); consistent with the summary's "incomplete cost analysis".
13. **EDA script exception swallowing**: `analyze_file` stores `str(e)` into the report and continues (`eda_analyzer.py:232-235`, `:300-305`); a failed parse yields a report with an "error" key that the LLM may or may not notice. Mitigation in our design: profiler failures are hard errors.

## 7. Verifier / evaluation / safety handling
- **Verifier tier**: effectively T5 only (LLM critic + LLM approval + keyword parsing). No executable verifier in the loop; benchmark scoring happens externally (MLE-Bench/AIRS/SciCode graders). Experiment correctness relies on the agent running code and the prompt rules (baseline, CV, uncertainty) (`experiment_agent_prompt.yaml:124-130`); nothing enforces them.
- **Anti-exploit**: none seen (no perturbed evaluator, no mutation test, no leakage check). The ideation search has no check that evolved ideas are novel versus literature other than prompt text.
- **Sandbox**: local `uv` project dir + cwd switch (`code_env.py`), bash classification into read-only/write/dangerous with a name/pattern blocklist, DANGEROUS_PATHS list (`permissions.py:52-65`), plan mode, and per-tool `check_permissions`. No network policy, no resource caps in the code I read.
- **Approval modes**: interactive web/CLI user approval vs headless approval subagent that verifies artifact existence (`approval_subagent/execute.py:38-60`). It checks "claimed files exist/non-empty", not metric correctness.
- **Tests**: 27 test files, mostly unit tests with mocked LLM (`tests/idea_search_test.py` header: "mock ModelRegistry.completion"); no integration test of a mechanism claim.

## 8. Bottom line
