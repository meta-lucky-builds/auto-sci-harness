## 1. What the code actually does (architecture map)
SoL-Pi is a Pi (`@earendil-works/pi-coding-agent` 0.85.1) extension package. `src/sol-pi/index.ts:175-177` default-exports an extension that, on `session_start`, loads `sol-pi.json` and registers only the enabled mechanisms (`index.ts:148-158`; all four default to `false`, `config.ts:27-36`). Config is strict: unknown keys throw (`config.ts:82-84`), project config honored only if the project is trusted (`config.ts:47-58`). Four mechanisms, each hooking Pi's public event API (no Pi patches):

| Mechanism | Hook | What it really does |
|---|---|---|
| Action Fusion | replaces built-in `edit`/`write` tools (`action-fusion/index.ts:86-152`) | adds optional `then_run:{command,timeout}`; applies mutation, then runs a bash command inside one per-file queue slot, returns ONE combined result (`then-run.ts:247-295`) |
| ObservationPack | `pi.on("context")` projection + `obs_recall` tool (`observation-pack/index.ts:317-462`) | tool results >10 KiB are archived to disk; after 2 provider requests the message is replaced in the projected context by a ~1 KB head+tail placeholder with a pageable recall handle |
| Evidence-Preserving Reducer (EPR) | `pi.on("tool_result")` (`reducer/index.ts:182-196`) | for build/test-command logs, calls a cheap model to extract quoted evidence, validates every quote byte-for-byte against the archived log, otherwise falls back to the raw log |
| Online Context Compact (OCC) | `update_plan` tool + `turn_end`/`agent_settled`/`session_compact` hooks (`extension.ts:232-495`) | decides WHEN to invoke Pi's native LLM-summarizing compaction, using a cache-cost break-even model, at plan-step completion boundaries |

Important: OCC does not itself compact; it calls Pi's `context.compact()` (`extension.ts:392`) with fixed instructions (`:38-39`). The summarization is Pi's native LLM compaction. The novelty is the economic trigger + safe boundary, not the rewrite.

## 2. Core loop, step by step (with file:line citations)
There is no search loop in this repo (see scoping fact). The runtime "loop" per mechanism:

**OCC (the most interesting, the cost-as-objective piece)**
1. Agent calls `update_plan` with full step list (+ optional `progress{files_changed,verification,decisions}`) (`tools.ts:44-101`). `analyzePlanTransition` detects a step moving non-completed -> completed (`plan.ts:312-333`); newly-introduced completed steps are history, not boundaries (`plan.ts:319`).
2. `recordBoundary` stores the number of provider requests since the previous boundary into `completedBoundaryRequestCounts` (`state.ts:recordBoundary`; used as the horizon sample). `pendingBoundary` set (`extension.ts:241-245`).
3. On the next `turn_end`, it requires a clean assistant turn and a non-error plan tool result (`extension.ts:303-313`), computes `writeTokens` (max of Pi-reported usage and own estimate, `:225-230`), `archiveTokens` = tokens of the span native compaction would summarize, priced on the *provider-visible projection* (i.e. after ObservationPack rewrites) via `estimateNativeCompactionTokens`/`projectedEntryTokens` (`extension.ts:152-179`, `projection.ts:353-395`), and calls `decideCompaction` (`:331-349`).
4. `decideCompaction` (`economics.ts:129-257`): saving = archiveTokens − memoTokens (fixed estimate 1000, `extension.ts:37`); `newDebt = postCompactionTokens × (cacheWriteReadRatio − 1)` (default ratio 12.5, `config.ts:14`); `breakevenRequests = newDebt / saving` (`:163-164`). Expected remaining requests = 1 + floor(mean requests-per-boundary × remaining unfinished plan steps × scale), capped by `(window − ctx)/avg positive context increment` (`economics.ts:77-127`). Compact iff `compressible && (windowProtection || (economic && !cooldown))` (`:205-212`). First compaction: horizon is doubled (`firstCompactionRequestScale=2`, `:176`); later ones need `breakeven × 1.5 <= horizon` and carried-debt gate (`:194-204`); cooldown of 2 requests (`:206-209`); window protection when ctx ≥ window − 16,384 overrides everything (`:180-182`).
5. If decided: stores `selected`, calls `context.abort()` (`extension.ts:356-357`), and in `agent_settled` runs `context.compact(...)` (`:392`), then re-triggers the agent with a hidden reminder message via `pi.sendMessage(..., {triggerTurn:true})` (`:445-452`). Recoverable compaction errors are whitelisted (`:48-52`); on failure `compactionRefused` suppresses retries until real tool work happens (`:299`, `:430-434`).
6. `session_compact` records cache debt/repayment so later decisions account for already-paid rewrite cost (`state.ts:recordCompaction`; `extension.ts:475-487`). User "CORRECTION:" input or a steer resets the horizon state (`:277-293`, `state.ts:recordCorrection`).

**ObservationPack**: per `context` event, compute how many assistant messages already followed each tool result (`index.ts:394-400`); for pure-text, non-error results >10 KiB (`observation.ts:12-13,67-74,102`) store content-addressed `obs_<24hex>` file with O_NOFOLLOW/O_EXCL and byte-verify on reuse (`observation.ts:123-156`); first `FULL_SENDS=2` requests send full, afterwards replace with `placeholderFor` (id, tool, bytes, lines, est. tokens, recall instruction, head 512 B + tail 512 B on whole-line boundaries) (`observation.ts:178-197`). Rewrites only the projection, never stored history (`index.ts:452,461`); fails open on any error (`:454-458`). `obs_recall(id, offset)` pages 15.5 KiB / 398 lines (`:293-301`). JSONL ledger of full/placeholder/recall events (`ledger.ts`).

**EPR**: gate chain in `reduceToolResult` (`reducer/index.ts:58-177`): tool must be bash, or write/edit with `then_run` (`candidate.ts:284-321`); command must match `DIAGNOSTIC_COMMAND` regex (pytest, cargo, make, lean, go test, ...) (`config.ts:25-26`); body ≥4096 B (`:17`) and ≤600k chars (`:18`); not matching `LIKELY_SECRET` (`:29`). Archives body by sha256 (`archive.ts:35-53`), calls reducer model (default `openai-codex/gpt-5.6-luna`, `config.ts:22-23`; 2048 max tokens, 90 s timeout, `cacheRetention:"none"`, `provider.ts:~125-135`) with a "lossless reducer" prompt that treats the log as untrusted (`receipt.ts:358-373`). `validateReceipt` (`receipt.ts:403-465`) checks: JSON parse, schema id, `source_sha256` equals archive hash, status equals actual `isError`, ≤12 evidence items, each quote ≤600 chars and `body.includes(quote)`, kind in a closed set, and — if the run errored and a failure-word regex hits the body — at least one `fatal|failure` evidence item. Receipt must be strictly smaller than source (`index.ts:137-148`). Every failure path journals a `fallback` and returns `undefined` (raw log passes through). Receipt tells the agent that "Sol retains ... adjudication" and how to read back the archive (`receipt.ts:493-496`).

**Action Fusion**: `then_run` skipped if mutation fails (`then-run.ts:213-217,267-273`); before running the command, hashes the file twice across a macrotask yield to detect interference (`then-run.ts:223-237`); non-zero command exit raises an error that includes the mutation output plus `[then_run:failed]` (`:291-293`) so the edit is kept but the failure is visible. Markers are later parsed by EPR (`candidate.ts:232-233,295-320`) so the mechanisms compose.

## 3. Paper/summary vs code discrepancies
- **Entire search methodology is absent from the repo** (152 hypotheses, 6 families, oracle analysis, Ralph loop, implementer/reviewer, capability+efficiency gates, EdgeBench 11/40 split, cross-model transfer harness, 3,000+ runs). Only the four end-products are shipped. Nothing about how hypotheses were generated or tested can be confirmed or reused from code. README only points to the paper and a blog.
- Summary says OCC "Rewrites prompt cache to remove redundant context". Code: it triggers Pi's native LLM summarization compaction (`extension.ts:392`); there is no direct cache manipulation. The "cache" enters only as the cost ratio in the break-even formula (`economics.ts:160-164`). The summary's "compares projected input savings against rewrite cost estimate" is accurate in spirit, but the "rewrite cost" is `postCompactionTokens × (ratio−1)` of re-written cache, with NO term for the summarizer call's own input/output cost [inference — I found none in `economics.ts`; memo size is a fixed constant 1000, `extension.ts:37`].
- Summary says OCC fires "at plan boundaries". True, but only if the agent uses the injected `update_plan` tool and registers steps before completing them (`tools.ts:56-61`, `plan.ts:319`). Without disciplined plan use it never fires except via window protection [inference from `extension.ts:299-313`].
- Summary says ObservationPack transmits full "first two agent requests": code counts assistant messages after the result (`index.ts:394-413`, `FULL_SENDS=2`); fine. "~1 KB excerpt" = 512 B head + 512 B tail by whole lines (`observation.ts:178-197`).
- Summary says EPR "Extracts deterministic evidence via schema verification". More precisely: a model extracts, code verifies quote *existence* only. It does not verify that the quotes are the *right* or *complete* evidence (see §6). "Deterministic" applies to the verifier, not the extraction.
- Summary: "Humans write harness code; AI reviewers verify" — cannot check; no code of the loop.
- Summary: EPR "scope: build and test logs" — code is a regex over command strings (`config.ts:25-26`), so non-matching commands (e.g. `./run_tests.sh`, `tox`, `gradle`) are never reduced. Narrower than the prose suggests.
- ObservationPack is skipped for `isError` results (`observation.ts:67-72`), so failed-test logs from fused commands (thrown as errors, `then-run.ts:293`) are never packed; and reducer receipts are never re-packed (`observation.ts:28,80-82,100`). Design choice worth noting; not in summary.

## 4. Mechanisms worth adopting into custom-harness (ranked by expected value)
Context: our `ContextPolicy` is two fields, `max_value_chars=20000` and `head_fraction=0.5` (`src/custom_harness/runtime/spec.py:70-72`), applied by `truncate()` inside `render()` to every templated value (`runtime/template.py:27-45`) and in `engine.py:_execute` for tool commands (`engine.py:205-243`). It is stateless, per-value, loses the middle irrecoverably, ignores token cost/cache pricing, and is not a searchable edit type. Our graph is a DAG of single-shot LLM/Tool/Module nodes, NOT a long-running conversation, so conversation-level OCC maps less directly than ObservationPack/EPR.

1. **Handle + paged recall instead of truncation (ObservationPack pattern)** — Cite `observation.ts:178-197`, `index.ts:317-387,429-452`. Better than ours because truncation (`template.py:27-33`) drops the middle with no way back, while this keeps head+tail excerpts, exact size metadata, and an addressable recall. Our L2 `BlobStore` is already content-addressed and write-once (`store/blobs.py:27,33`), so the archive half exists. Layer: L0 runtime (ContextPolicy) + L2 store. Effort: S-M (add `ContextPolicy.mode: "truncate"|"handle"`, `excerpt_bytes`, `full_sends`, and a built-in `recall` ToolNode/Module that reads a blob by id+offset; keep truncation as fallback). In our single-shot nodes "full_sends" becomes "inline N times across downstream nodes" or just "always handle above threshold". Reimplement (Python; MIT permits copying with attribution but the code is TS/Pi-specific). Keep their `fail-open` rule (`index.ts:454-458`) and projection-only rewrite (never mutate stored state) — fits our trace-fidelity principle. Also make threshold/excerpt/full_sends typed edit parameters so L6 can evolve them.
2. **Verified-quote reducer with raw fallback (EPR pattern)** — Cite `receipt.ts:403-465`, `index.ts:58-177`. Adopt for ToolNode outputs (pytest/training logs from sandbox) before they enter the next LLM prompt: cheap model extracts quotes; deterministic code checks substring/hash/status; any failure -> raw (head/tail) log. Our `res.model_dump()` tool output currently goes straight into state and then through truncation (`engine.py:210-220`). Layer: L1/L3 (deterministic verifier of an LLM-produced artifact) feeding L4. Effort: M (a `reduce_log` ModuleNode using our gateway, sha256 check, journal records to L2 as evidence). Reimplement. Strengthen over theirs (see §6): require line-anchored quotes, add an independent tail/first-error mandatory inclusion rule computed deterministically (e.g., always include first traceback and final summary line by regex, don't trust the model to select them), and log reducer-vs-raw outcome so L6 can measure false-reduction.
3. **Cost-as-objective with explicit break-even economics (OCC decision model)** — Cite `economics.ts:129-257`. The reusable idea is not the Pi hook but the *decision rule*: act only if `(cost of rewrite) / (per-request saving) <= expected remaining requests`, with horizon estimated from observed history (`economics.ts:77-127`), a conservative-first/stricter-subsequent margin, carried cache-debt accounting (`state.ts:recordCompaction`), cooldown, and an absolute window-protection override. Better than ours: we only have hard budget caps (`budget.py`) and a capability-only score (`evolve/evaluate.py:74-87` returns `1.0*verified + 0.5*rel`, cost is recorded in `RunOutcome.cost` but not in the objective). Layer: L1 (control plane budget/pricing) + L6 (objective). Effort: M. Reimplement (pure arithmetic). For our graph, apply the same rule to "should this node's input be compacted/handle-ified" using per-provider cache price ratio in `providers.yaml` and node re-execution counts (retries/loops). Caveat: add the summarizer-call cost term that SoL-Pi omits.
4. **Cost-aware, dual-gated harness selection** (design idea from the paper, NOT visible in code) — "capability gate within predeclared tolerance AND efficiency gate" as independent sequential gates; plus reporting score-retention % and cost reduction %, and Pareto fronts instead of one scalar. Maps to our `evolve/selection.py` gate (non-regression eps + bootstrap CI) — extend `gate()` with a cost axis (`cost_ratio` CI, accept only if capability non-regression passes AND cost improves, or vice versa for a "frontier" mode). Layer: L6. Effort: S-M. Idea only (we have no code to copy). [Unverified against full paper.]
5. **Frozen-mechanism / one-way feedback discipline** (paper-only; summary says dev results feed hypothesis generation but "never into final search"; EdgeBench 11 for one-way acceptance, 40 for generalization; cross-model transfer as a robustness check). We already have evolve/gate/sealed splits (`evaluate.py:7,24`). Concrete additions: (a) record per accepted harness the model it was evolved on, and require a transfer run on a second backend family before it becomes a "mechanism" in the ledger; (b) make the sealed split strictly one-shot per frozen candidate set (count touches). Layer: L6/L9. Effort: S. Idea only.
6. **Action Fusion (`then_run`)** — Cite `then-run.ts:247-295`. For coding sub-agents inside our sandbox loop (implement/fix), allow edit+run in one tool call; removes one LLM round trip. Includes the TOCTOU guard (hash the file before and after a yield, `then-run.ts:223-237`). Layer: L0 tools / L4 implement-fix node. Effort: S-M, but only valuable if/when we have a free-form tool-using agent node; our current graph already routes implement->run via deterministic edges ("deterministic routing", STATUS.md) [inference: therefore partly already achieved structurally]. Reimplement.
7. **OCC plan-boundary compaction itself** — lowest priority for us until we have multi-turn agent nodes. If/when added (conversation-carrying LLM nodes in L4), compact only at plan-step completion, use the projection-aware token pricing trick (`projection.ts:353-395`, price what the provider actually sees after other rewrites), and the abort->settle->compact->continue sequence (`extension.ts:356-357,360-473`). Effort: L. Reimplement.

## 5. Things custom-harness already does better (with evidence)
- **Trace fidelity / exact replay**: ours has full per-step traces, checkpoints, exact fork/backtrack (`runtime/`, STATUS.md). SoL-Pi has only ad-hoc JSONL ledgers per mechanism (`ledger.ts`, `journal.ts`) and relies on Pi's session log; OCC state is lossy by design.
- **Held-out discipline in code**: we implement evolve/gate/sealed split machinery, paired bootstrap CI, racing, lineage including rejects (`evolve/loop.py:75-128`, `evaluate.py:7`). SoL-Pi ships none of this in the repo (paper-only).
- **Private-data leakage guard**: `_private*` state can never render into a prompt (`template.py:36-47`). SoL-Pi has no analogue (not applicable to its scope, but we are stronger on leakage).
- **Typed, diffable harness edits + predicted effects + calibration** (`evolve/edits.py`, `propose.py`, PLAN §6/§8.5): SoL-Pi's mechanisms are hand-coded extensions with a boolean on/off config (`config.ts:16-25`), not an evolvable spec.
- **Sandboxed execution**: ours runs agent code in Docker with no network/caps; SoL-Pi explicitly "is not a sandbox or permission boundary" (SECURITY.md) and Action Fusion runs arbitrary model-requested bash in the host process.
- **Verifier tiers / evidence store with claims-only-from-evidence** (L2/L3): SoL-Pi has no claim or verifier concept beyond the reducer's quote check.

## 6. Pitfalls, bugs, or anti-patterns seen in their code (cite) that we must avoid
- **EPR verifies existence, not relevance or completeness.** `validateReceipt` only needs each quote to satisfy `body.includes(quote)` (`receipt.ts:440`); a 1-character quote that occurs anywhere passes (`:438` only rejects length <1). A model can quote harmless lines and omit the real cause; the only completeness check is one regex-based rule requiring ≥1 fatal/failure item when `isError && FAILURE_SIGNAL.test(body)` (`:457-463`), and `FAILURE_SIGNAL` is a loose keyword regex (`config.ts:28`). On `isError=false` (e.g., exit 0 with failing tests printed), nothing is enforced. Mitigation we should add: deterministic mandatory-evidence extraction (first traceback, last N lines, summary lines) done in code, plus minimum quote length / line-anchoring.
- **Quote lookup uses first occurrence** (`lineNumberOf`, `receipt.ts:388-396`), so reported line numbers can be wrong for repeated lines; `quote_sha256` gives false rigor.
- **Command-gating by regex on the command string** (`config.ts:25-26`) is brittle (misses wrappers/scripts; matches substrings like `make` anywhere preceded by `;&|()` or space).
- **Secret scan is a heuristic** (`LIKELY_SECRET`, `config.ts:29`); SECURITY.md concedes it is not a complete scanner, yet logs are sent to a remote model. We must keep our `gateway` redaction and never send sandbox logs off-box without it.
- **OCC cost model omissions**: no term for the summarization call's own cost; `memoTokens` is a constant 1000 (`extension.ts:37`) rather than measured; `contextTokens` = max(reported, estimated) so it may overestimate write cost (`extension.ts:229`); the horizon is the mean requests-per-plan-step × remaining steps — fragile with few samples (variance option exists but `remainingRequestStddevK` defaults to 0, `economics.ts:19`, so uncertainty is ignored by default). The 12.5 write/read ratio is a hard-coded Anthropic-like constant (`config.ts:14`) applied regardless of provider; the paper itself notes cache paradox [summary]. If a provider has no prompt caching, the model is wrong. Make ratio per-provider from `providers.yaml`.
- **OCC depends on model cooperation**: boundaries exist only if the model keeps calling `update_plan` correctly; there is advice text but no enforcement (`plan.ts:326-330`). Silent no-op otherwise.
- **OCC deliberately aborts the agent turn** (`extension.ts:357`) and restarts it with a hidden message; large complexity (≈500 lines of races, continuation promises, Pi-version-specific print-mode barriers, `:458-466`). High bug surface; test files exist but I did not read them.
- **Observation placeholders prune permanently from the model's view**: the model must choose to call `obs_recall`; no guarantee it does. Savings are measured as removed tokens (`index.ts:431`), never quality impact; the paper itself reports ObservationPack "becomes more selective" in the full stack without explanation [summary].
- **Error results never packed** (`observation.ts:67-72`): large failure logs still cost full price on every request (unless EPR reduces them).
- **Time-of-check guard in Action Fusion is weak**: it compares file hashes across one `setImmediate` yield (`then-run.ts:223-237`), which catches only very tight races; and the then-run command runs unsandboxed.
- **Efficiency claims measured on a tiny frozen set** (summary: 40 held-out tasks; Terminal-Bench 15 vs 18 solved) — a real capability loss for 26% cost saving. Treat "93.7% retention" as a trade-off, not a free lunch; our gate should refuse capability regressions beyond a CI-based tolerance, not mean-based.
- **Nothing in-repo to audit regarding overfitting**: all selection evidence lives outside the repo; do not import their numbers as a prior.

## 7. Verifier / evaluation / safety handling
- In code, the only verifier is EPR's receipt validator (`receipt.ts:403-465`) with fail-open to raw output on ANY problem (`index.ts:93-148`: timeout, model unavailable, bad JSON, schema mismatch, unverifiable quote, missing failure evidence, receipt not smaller, likely secret, source too large). Fail-open is the correct polarity for a cost optimizer: the worst case is baseline behavior. Adopt this "optimization may never reduce evidence" invariant.
- Anti-injection: reducer prompt marks the log `<untrusted_log>` and instructs to ignore embedded instructions (`receipt.ts:362,382-384`), but defense is only the quote check and a restricted JSON schema; the receipt's `authority=` line tells the agent the main model retains adjudication (`receipt.ts:494`) — a useful trust-boundary pattern (reduced evidence never decides pass/fail).
- File safety: O_NOFOLLOW/O_EXCL, 0700/0600 modes, byte-verify of existing content-addressed objects (`observation.ts:21-22,123-156`; `archive.ts:42-52`), reading of Pi's temp bash log only if a regular non-symlink `pi-bash-*.log` directly in tmpdir (`candidate.ts:254-262`). Good hygiene for any content-addressed archive we add.
- No sandbox of agent code (SECURITY.md); no benchmark/evaluation code, exploit handling, held-out management, or reward-hacking checks exist in this repo. Those live in the (unreleased) search infrastructure. The summary's claims about predeclared tolerances and sequential gates are unverified here.

## 8. Bottom line (5 lines max)
- The repo is only the four frozen end-product mechanisms (~3.6k LoC TS, MIT); the 152-hypothesis search, Ralph loop, gates, held-out/transfer protocol are NOT released, so their methodology cannot be code-reviewed or reused.
- Highest-value ports: handle+paged-recall instead of head/tail truncation (our `ContextPolicy`, `spec.py:70-72`), and a verified-quote log reducer with raw fallback; both fit our content-addressed L2 blobs and are cheap to reimplement in Python.
- Most transferable idea is the explicit cost break-even decision rule (`economics.ts:129-257`) and putting cost on the objective axis: our `score_state` is capability-only (`evolve/evaluate.py:74-87`); add a cost axis to the gate with Pareto reporting.
- Avoid their weaknesses: existence-only quote verification, regex command gating, missing summarizer-cost term, hard-coded 12.5 cache ratio, reliance on model discipline for plan boundaries.
- We are already stronger on trace fidelity, split/gate machinery, leakage guard, typed edits, and sandboxing; adopt the discipline (fail-open, frozen mechanisms, transfer check), not the code.
