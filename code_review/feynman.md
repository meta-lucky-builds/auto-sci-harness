## 1. What the code actually does (architecture map)
Feynman is **not a standalone agent loop**. It is a configuration pack for the third-party "Pi" coding-agent runtime (`@earendil-works/pi-coding-agent`), declared in package.json `pi` block: `extensions: ./extensions/research-tools.ts`, `prompts: ./prompts`, `skills: ./skills`, `subagents.agents: ./.feynman/agents`. Consequences:
- The "four agents" (researcher, writer, verifier, reviewer) are **markdown files with YAML frontmatter and a system prompt** (`.feynman/agents/*.md`). Parallelism, subagent spawning (`subagent` tool, `workflow` scripts, `runs.all`, `bg_wait`) comes from the external `pi-subagents` package. None of that code is in this repo, so I cannot say how concurrency is implemented. The only in-repo mention is `src/pi/settings.ts:191-201`, which makes `research-tools.ts` and `pi-web-access` load into every child session so researcher and verifier keep their search tools.
- The orchestration "workflow" is a **natural-language prompt** (`prompts/deepresearch.md`, `prompts/lit.md`). The lead LLM follows it. No state machine, no code enforcement of step order. The only deterministic gates are prompt rules such as "Do not run the verifier and reviewer in the same parallel `subagent` call" (deepresearch.md:118).
- The only real TypeScript on the evidence path is the **literature tool** `feynman_science_database_search` (`science-databases.ts:442-491`), plus `alpha_*` tools (`alpha.ts`, wrapping the external alphaXiv client `@companion-ai/alpha-hub`) and Hugging Face tools (`huggingface.ts`, not read in detail).
- There is **no database, no claim graph, no structured evidence store**. State is markdown files in the workspace: `outputs/.plans/<slug>.md`, `outputs/.drafts/<slug>-research-*.md`, `-draft.md`, `-cited.md`, `-verification.md`, `-revised.md`, and final `outputs/<slug>.md` plus `<slug>.provenance.md` (deepresearch.md:13-20, 166-179).

Retrieval behaviour that matters:
- **Cross-index fallback**: `withIndexFallback` (science-databases.ts:402-419) retries a rate-limited/timeout/5xx topic search on the other general index (Semantic Scholar <-> OpenAlex) and prepends a `fallbackNote`. ID/DOI/author/citation lookups do not fall back (`OPENALEX_LOOKUP_QUERY`, :385-386).
- **Per-host request pacer** (`request-pacer.ts:4-17`): a promise queue guaranteeing a minimum gap between request starts, because parallel tool calls from sibling subagents share a process and got 429s (comments at science-databases.ts:141-146, arxiv.ts:32-34).
- **Uniform result schema and provenance**: every result carries `schema: "feynman.scienceDatabaseSearch.v1"`, `source`, `query`, `totalCount`, `returned`, `results[]`, and `provenance: {docs, endpoints[]}` listing the exact URLs hit (e.g. science-databases.ts:198-209, 365-380). Stable IDs (DOI, arXiv ID, PMID, S2 paperId, OpenAlex W-id) are preserved. The tool's promptGuidelines tell the model to keep them in artifacts (:452).
- **Source routing is a prompt table**, not code (researcher.md:26-35). Researcher is told to run 2-4 reworded queries per question and merge, since "seminal papers often appear only under one phrasing or one sort order" (researcher.md:37).
- Retrieval returns abstracts/metadata. Full text is read ad hoc via `fetch_content` on arxiv.org/html or Europe PMC. There is **no persistent index, no embeddings of our own, no dated snapshots, no cache**. [inference] Every run re-queries live APIs, so results are not reproducible and cannot be frozen at a date T. `current-date.ts` only injects today's date into the system prompt.

## 2. Core loop, step by step (with file:line citations)
`/deepresearch` (prompts/deepresearch.md), prompt-driven:
1. **Plan** (:22-38). Write `outputs/.plans/<slug>.md` (questions, evidence needed, scale decision, task ledger, verification log, decision log), then **stop and ask the user to approve**. `/lit` skips approval (lit.md:13).
2. **Scale decision** (:40-52). "What is X" explainer or <=10 tool calls means the lead searches directly. 2-3 researchers for comparison, 3-4 for a survey, 4-6 for multi-domain. Direct mode needs >=3 distinct queries, with the exact search terms logged to `-research-direct.md` (:61-62).
3. **Gather** (:54-90). Lead writes per-researcher briefs `<slug>-T1.md`, then a JS workflow file `return await runs.all([...])` and launches it with `subagent({workflow, async:true, globalConcurrencyLimit:4})` (:71-87). Each researcher writes `outputs/.drafts/<slug>-research-<x>.md`. The lead must check which outputs exist on disk and not assume success (:72, 90). If a PDF parser fails, researchers continue from abstracts and mark PDF parsing "blocked" (:73).
4. **Draft** (:92-108). The lead writes the draft itself ("Do not delegate synthesis"). The draft contains **no citations** at this stage (writer.md:49-50 forbids them). A pre-citation sweep requires every number/figure/table to map to a URL, note, artifact path, or command output.
5. **Cite = Verifier** (:110-131). Only if researcher subagents were used. Direct-search runs have the lead do the citation pass itself and **"Do not spawn the verifier subagent for simple direct-search runs"** (:112-116). The verifier is async, awaited, and its output file `-cited.md` must exist on disk before review.
6. **Review** (:133-158). A reviewer subagent (or the lead, in direct mode) checks the cited draft and writes `-verification.md` with FATAL/MAJOR/MINOR findings. FATAL means fix and re-review once, MAJOR goes into Open Questions, MINOR is accepted. Large fixes go to a full rewrite `-revised.md`, not many small edits (:156).
7. **Deliver** (:160-183). Copy to `outputs/<slug>.md` or `papers/<slug>.md` and write the provenance sidecar. Verify on disk that all artifacts exist. Use `Verification: BLOCKED` if checks could not be run.

Note the sequencing: the verifier and reviewer are **sequential, not parallel** (:118: never in the same parallel call). The verifier runs after the draft exists, alongside nothing. Only the *researchers* run in parallel.

### The Verifier, exactly (`.feynman/agents/verifier.md`)
It is an **LLM subagent with a prompt**, not code. Tools: `read, bash, grep, find, ls, write, edit, web_search, fetch_content, get_search_content, feynman_science_database_search` (:5). `thinking: medium`. Procedure by its own instructions:
1. **Anchor** every factual claim to a source in the research files and insert `[n]` (:14).
2. **URL liveness**: `fetch_content` each source URL "to confirm each URL resolves and contains the claimed content" (:15, 31-36). Live = keep. Dead/404 = search for an archive/mirror, else **drop the source and every claim that depended solely on it**. Redirect to unrelated content = dead.
3. **Identifier cross-check against two indexes** (:38): for each cited paper, cross-check DOI or arXiv ID via `feynman_science_database_search` with `arxiv` or `crossref`, plus `openalex` or `semanticscholar`. Confirm **title, year, first author** match. Flag mismatches in the output rather than silently keeping the citation. Note which record (preprint vs venue) was matched.
4. **Semantic support**: "A citation is valid only if the source actually supports the specific number, quote, or conclusion attached to it" (:18). [inference] This is performed by the LLM reading fetched content. No entailment model, no quote-span extraction, and no required evidence field (see sec. 6).
5. **Structural invariants** stated in prose (:24-29): every claim has a citation, no orphan `[N]`, no orphan source, hedged/opinion statements exempt, merge numbering across research files and dedupe sources.
6. **Result provenance audit** (:46-56): scan for numeric scores, benchmark names/tables, figure refs, superiority claims, dataset sizes, charts. Each must map to a URL, research note, artifact path, or script path. Otherwise remove or replace with TODO and add a "Removed Unsupported Claims" section.
7. **Fake-certainty ban**: do not write "verified/confirmed/reproduced" without underlying evidence (:19; SYSTEM.md:128).
Output: the full document with inline citations plus a Sources section. It is a rewrite of the draft, not a separate machine-readable report.

What is **not** in the verifier: no per-citation structured record (status, matched title, evidence quote), no failure counters, and no code that enforces the orphan rules. Nothing programmatically checks that the verifier did what it claims.

### Report generation with provenance
- Per-source provenance exists at **tool level** (endpoints list, stable IDs) and at **researcher level**: an evidence table `# | Source | URL | Key claim | Type (primary/secondary/self-reported) | Confidence`, plus a `Coverage Status` section of what was checked directly vs uncertain (researcher.md:70-98). Integrity commandments: no URL means not included, read before summarize, mark inference vs direct read (:12-18).
- **Report-level provenance** is a markdown sidecar with: date, rounds, sources consulted / accepted / rejected, `Verification: PASS | PASS WITH NOTES | BLOCKED`, plan path, research files (deepresearch.md:168-179). Free text written by the lead LLM. Nothing validates it. The only check is the lead "verifying on disk" that files exist (:181).

## 4. Mechanisms worth adopting into custom-harness (ranked by expected value)
Our current state: `research/modules.py:323-356` has I1/I2/I4 and `I3 = "n/a"` (STATUS.md:36). PLAN.md:125 defines I3 as "every citation resolves to a retrieved document whose text supports it". Feynman does **not** implement I3 deterministically (sec. 2), but it provides most of the ingredients.

1. **Deterministic citation resolution check = I3 part 1 (eval/run.mjs:105-198)**. `extractIds` regex-extracts arXiv IDs and DOIs from the final report (run.mjs:105-114 region; `extractIds`), `resolveArxiv` batches IDs 50 at a time through arXiv `id_list` at 3.1 s spacing, and `resolveDoi` hits Crossref `/works/<doi>` then falls back to the `doi.org/api/handles` API for non-Crossref DOIs (DataCite etc.). Each ID is classified `resolves = true | false | undefined (network failure, excluded)`. Tri-state is important: lookup failures are excluded from the denominator instead of counted as hallucinations. Then `titleOverlap` computes the share of the resolved record's title tokens present in the text lines that cite the ID (>=0.6 passes), with a first-author-surname fallback for author-year citations (`scoreCitations`, `citedContexts`). Output metrics: `citation_validity`, `title_match`, lists `unresolved` and `title_mismatch` (run.mjs:~170-198). Why better than ours: we have nothing for I3. This is the reproducible part we can build. Layer: **L2/L3 audit pass (I3), T3 or hard-check tier**, plus a new `literature/` module. Effort: **S-M** (Python, httpx; pacing from request-pacer idea). Copy-vs-reimplement: **reimplement** in Python (the code is JS, and it is small and simple); MIT permits copying with attribution if we ever port line-by-line.
2. **Typed Citation evidence records + a post-hoc verifier that emits structured results**, a superset of Feynman. Feynman's verifier output is just a rewritten markdown. We should produce per-citation `Evidence(kind=citation)` rows (PLAN.md:63) containing: identifier, resolver used, matched title/year/first author, status {resolved, id_mismatch, title_mismatch, dead, unreachable}, and for "supports" claims a **quote span from retrieved text**. This turns Feynman's prompt rule "valid only if the source supports the specific number/quote/conclusion" (verifier.md:18) into an auditable object. Layer L2 + L4.8 (audit). Effort M. Reimplement (idea only).
3. **Two-index cross-check with explicit "which record matched" semantics (verifier.md:38)**. Check arXiv or Crossref plus OpenAlex or Semantic Scholar and compare title/year/first author. It acknowledges preprint vs venue records differ. This is cheap and catches the most common LLM citation failure (real ID, wrong paper). Where: I3 resolver. Effort S. Reimplement.
4. **Uniform tool result envelope with endpoint provenance** (`schema/source/query/totalCount/returned/results/provenance.endpoints`, e.g. science-databases.ts:198-209, 365-380) and **fallbackNote-first** semantics (:417). For our literature module, every retrieval becomes a content-addressed blob in L2 containing the exact request URLs and timestamp, giving auditable provenance and a basis for dated snapshots (which Feynman lacks). Layer L2/L4.3. Effort S-M. Reimplement.
5. **Retrieval hygiene from real failures**: shared per-host request pacer with min start gap (`request-pacer.ts`), per-host limits (arXiv 3 s, Crossref 1.2 s/0.4 s polite, S2 retry <=5 s), cross-index fallback for topic search only (not for exact lookups), and dropping arXiv topic search. Also **citation-sorted bulk Semantic Scholar** as the default because relevance ranking misses seminal papers and anonymous relevance is rate-limited (science-databases.ts:323-328, 335-340). Effort S. Reimplement (our gateway layer should own pacing).
6. **Multi-phrasing query fan-out + merge** (researcher.md:37) and openalex `search.semantic` for conceptual matches (openalex.ts:545-550). Feeds the hypothesis/literature step (L4.3). Effort S.
7. **Result-provenance audit as a rule set** (verifier.md:46-56; SYSTEM.md:124-130): any numeric score, benchmark, table, or figure must map to an artifact. We already implement the harder mechanical version as I1/I4. The extra idea worth lifting is the **ban on illustrative/simulated visuals** (verifier.md:43) as a lint on the report renderer.
8. **Eval design: fixed question set with expected key papers + deterministic scoring + "run before and after every prompt/tool change" rule** (evals/README.md "Rule", questions.jsonl). Includes recall of key papers by ID or normalized title (run.mjs `keyRecall`). Fits our scorecard section F (PLAN.md:337) and the literature part of the time-split set. Effort S. Reimplement.

## 6. Pitfalls, bugs, or anti-patterns seen in their code (cite) that we must avoid
1. **The core integrity guarantee is an LLM prompt, not code.** The verifier (verifier.md) and the "fixed-point" orphan rules (:26-27) are unenforced. The same model family that wrote the draft cites and checks it. [inference] A hallucinated citation can survive if the verifier LLM skips it. The only measurement of this failure rate is the offline eval, which is run manually and not as a gate in the product.
2. **Verifier is skipped on small runs by design** (deepresearch.md:112-116). That makes citation integrity conditional on a scale heuristic ("simple explainers"). We must run I3 on every report regardless of size.
3. **Eval regexes only recognize arXiv IDs and DOIs** (`extractIds`, run.mjs). Citations to web URLs, blog posts, PMIDs, or author-year-only references are neither resolved nor counted, so `valid`/`title` percentages can look 100% while much of the bibliography is unchecked. Treat their "100% valid" as a lower-coverage claim: e.g. the Opus run reports 85 cites with 100%/97% (results md) but only counts identifier-bearing ones.
4. **Title-overlap heuristic has acknowledged false positives/negatives** (README: short-name citations "also miss"; and a context line containing the title of an unrelated cited paper could pass). The check verifies *identity* (ID matches the named paper), **not that the cited paper supports the sentence it is attached to**. Feynman's evals do not measure claim support at all (README lists ScholarQA-CS2 / DeepResearch-Bench FACT as "not built yet"). So the "valid + title match" scores do not demonstrate I3 in our sense.
5. **Substantial model reliance on prompt-level control flow**: step ordering, "must complete before reviewer", async handles, `bg_wait`. The pre-wait eval shows the failure: an agent ended its turn while the reviewer was running, producing no provenance file (results/2026-09-24-lit-0.5.3-pre-wait-...-opus-5-5.md note). Fixed by adding a prompt rule to SYSTEM.md:120. We should keep step ordering in our graph interpreter, not in prose.
6. **Tool-argument sloppiness workarounds** (`prepareArguments`, science-databases.ts:455-465: models send "null"/"" for optional fields; deepresearch.md:68-70 and 156 on keeping `subagent` JSON small and avoiding giant edits). Evidence of fragile model-in-the-loop plumbing. We should use strict schemas with coercion at the gateway.
7. **Live APIs without caching or snapshots**: no cache, no frozen results, rate-limit pressure (pacers and 429 retries throughout). Runs are not reproducible, and time-split experiments (PLAN T4) are impossible on this design.
8. **Refusals on legitimate topics** (README of results: "Opus 5.5 refuses q04 and q07", CRISPR base editing). Model-side, but it shows evaluation must allow for provider-refusal outcomes as a distinct status rather than as a score of zero.
9. **Provenance sidecar is LLM-authored free text** (deepresearch.md:168-179); "Sources rejected" and "Verification: PASS" are self-reported.
10. Telemetry to PostHog is enabled by default (README "Telemetry"), irrelevant to us except as a reminder to keep BYOS/ToS handling in our provider registry.

## 7. Verifier / evaluation / safety handling
- **Product verifier**: LLM subagent, see sec. 2. Checks: URL liveness by fetch; DOI/arXiv ID cross-check against Crossref/arXiv plus OpenAlex/Semantic Scholar on title, year, first author; claim-to-source semantic support by reading; removal of unsupported claims; orphan citation rules; result-provenance audit. Reviewer then does a "verification pass" for unsupported claims, logical gaps, single-source critical claims, overstated confidence, with FATAL/MAJOR/MINOR severities (deepresearch.md:145-154; reviewer.md checklist).
- **Evaluation** (`evals/`): deterministic, no LLM judge (evals/README.md:3). Per question: isolated temp HOME and workspace (`runQuestion`, run.mjs:~46-70), run `/lit` or `/deepresearch` with a timeout (default 45 min), score the final output: done (final + provenance exist), `cites`, `valid`, `title`, `recall`, tokens, cost. Git SHA and dirty flag recorded. Re-scoring of kept workdirs supported (`--rescore`). Baselines checked in under `evals/results/`. 12 questions (6 from their own search benchmark, 3 from LitQA2, 3 hand-written). This is the strongest piece of engineering in the repo relevant to us.
- **Reward-hacking / exploit handling**: none in code. The only analogues are prompt rules ("results that look cleaner than expected are suspect", SYSTEM.md:127; "no aesthetic laundering", writer.md:7). No quarantine, no perturbation, no judge panel.
- **Sandboxing**: this repo does not execute agent code itself. `/audit` is designed not to execute (README table). I did not read `prompts/replicate.md` or `autoresearch.md`, so I make no claim about their sandboxing. Third-party Pi tools run `bash` with whatever isolation Pi provides (not read).
- **Secrets**: API keys come from env vars (`SEMANTIC_SCHOLAR_API_KEY`, `OPENALEX_API_KEY`, `CROSSREF_MAILTO`); `web-search.json` is chmod 0600 (web-access.ts:73-86); eval harness reads keys from env and does not write them (evals/README.md).

## 8. Bottom line
- The repo is a Pi plugin pack: the "four-agent parallel system with SQLite versioning and 40+ APIs" in our summary is mostly unsupported by code. In fact 8 literature sources, markdown files, and prompt-driven orchestration.
- Their citation "verifier" is an LLM prompt (verifier.md); the only deterministic citation checking is the offline eval (`evals/run.mjs`): ID resolves + title-token overlap, which checks identity, not claim support.
- Adopt for I3: arXiv/Crossref/doi.org resolution with tri-state results, two-index title/year/author match, structured per-citation Evidence records, and endpoint-level provenance in stored retrieval blobs. Add what they lack: quote-span support check, dated snapshots, caching.
- Adopt retrieval hygiene (per-host pacers, cross-index fallback, citation-sorted S2 default, OpenAlex semantic search) and their fixed-question, before/after eval discipline. MIT: copy allowed with attribution, but a Python reimplementation is easier.
- We are already stronger on enforced claim-evidence linkage, metric recomputation, tracing, sandboxing, and statistics.
