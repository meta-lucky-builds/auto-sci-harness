## 1. What the code actually does (architecture map)
A linear, single-pass pipeline per idea, driven by `launch_scientist.py`. No tree search, no memory beyond files in a per-idea folder.
- **Template** = a directory (`templates/<name>/`) holding `experiment.py` (the entire experiment, CLI `--out_dir`), `plot.py`, `prompt.json` (system + task description), `seed_ideas.json`, `latex/template.tex`, and a pre-computed `run_0/final_info.json` baseline (`launch_scientist.py:172`; the baseline is NOT produced by the harness, it must be prepared by hand per template).
- **Idea generation** (`generate_ideas.py:76`): LLM proposes ideas one at a time with up to `num_reflections` self-refinement rounds; archive of previous ideas (seed ideas + prior outputs) is pasted into each prompt as plain text (`:116`, `:121`).
- **Novelty check** (`:405`): LLM-driven literature search loop (Semantic Scholar or OpenAlex, top-10 abstracts per query, up to 10 rounds); LLM emits "Decision made: novel/not novel" (string match, `:448-454`).
- **Experiment loop** (`perform_experiments.py:116`): Aider `Coder` (diff edit format, no git, `yes=True` auto-confirm; `launch_scientist.py:198-216`) edits `experiment.py`, `plot.py`, `notes.txt`; harness runs `python experiment.py --out_dir=run_i` via `subprocess.run` (`:45`) with 7200 s timeout; stderr tail (1500 chars) or results dict is fed back as the next prompt.
- **Writeup** (`perform_writeup.py:401`): Aider fills `latex/template.tex` section by section (write pass + refine pass per section), then a Semantic-Scholar citation loop (up to 20 rounds) that appends real BibTeX, then a second refinement pass, then `chktex` + `pdflatex/bibtex` with up to 5 LLM-driven error-fix rounds (`generate_latex`, `:15`).
- **Reviewer** (`perform_review.py:126`): LLM (default GPT-4o) with NeurIPS review form, few-shot examples, N-sample ensemble + LLM "meta-review", numeric scores averaged, optional self-reflection rounds.
- **Improvement** (optional `--improvement`): feed the review JSON back to the same Aider coder ("Improve the text using the review", `perform_review.py:386`), recompile, re-review.
- **Open-ended variant** (`experimental/launch_oe_scientist.py`): interleaves `generate_next_idea` + novelty check + `do_idea`, writes review `Overall` back onto the idea as `"Score"` (`:390`), and the next idea prompt sees these scores (`generate_ideas.py:221-225`).
- **LLM layer** (`llm.py`): provider switch by substring match on model name (`:80`, `:197`...), `MAX_NUM_TOKENS = 4096`, `seed=0` for OpenAI-style calls, backoff only on OpenAI exceptions (`:66`, `:152`; Anthropic rate limits are not covered, [inference] since backoff is keyed to `openai.*` classes).

## 2. Core loop, step by step (with citations)
1. `launch_scientist.py:339-358`: create client, `generate_ideas(...)` (default 50 ideas, `NUM_REFLECTIONS=3`), then `check_idea_novelty` unless skipped. Ideas are saved to `templates/<exp>/ideas.json` (`:360`); the filter `novel_ideas = [i for i in ideas if i["novel"]]` (`:363`).
2. For each novel idea (sequential or GPU-per-process queue, `:366-419`; 150 s `time.sleep` between worker starts, `:390`): `do_idea` copies the whole template dir (`:171`), reads baseline `run_0/final_info.json` (`:172`), writes `notes.txt` with title/experiment/baseline (`:180-185`).
3. `perform_experiments` (`perform_experiments.py:116-166`): prompt = title + experiment text + baseline results (`coder_prompt`, `:12`). Loop: `coder.run(prompt)`; if the reply contains the literal "ALL_COMPLETED" stop (`:132`); else run experiment. On return code 0: next run index, reset retry counter; else retry (max `MAX_ITERS=4` consecutive failures, `:8`, `:127`). `MAX_RUNS=5` runs total. Failed runs delete their output dir (`:55`, `:82`) so only the stderr tail survives in the prompt.
4. Then plotting: Aider edits `plot.py` until `python plot.py` exits 0 (<=4 tries, `:153-158`), then Aider documents plots in `notes.txt` (`:159-164`).
5. Writeup (`perform_writeup.py:401-512`): abstract, then Introduction/Background/Method/Experimental Setup/Results/Conclusion each with a "refine" pass (`:422-448`); related work sketched as comments (`:451-462`); citation loop calling a separate LLM call to pick queries then S2 results, appending BibTeX into the `filecontents` block via string replace (`:465-481`); final per-section refinement (`:494-510`); `generate_latex`.
6. `generate_latex` (`:15-91`): deterministic checks only for (a) every `\cite` key is a substring of the bib text (`:34`), (b) every `\includegraphics` file exists in the folder (`:46`), (c) duplicate figures/sections, (d) `chktex` output; each failure sends a prompt to Aider. Compile with 30 s timeout per command (`:94-121`).
7. Review (`launch_scientist.py:267-278`): `perform_review(model="gpt-4o-2024-05-13", num_reflections=5, num_fs_examples=1, num_reviews_ensemble=5, temperature=0.1)`; the result is written to `review.txt`. It does not gate anything in the main pipeline (see 3, 6).

Reviewer internals: system prompt "negative" variant by default ("If a paper is bad or you are unsure, give it bad scores and reject it", `perform_review.py:18-21`, `:136`); 5 samples at temperature 0.75 via `n=5` (`:152-162`); a meta-review LLM call merges them (`get_meta_review`, `:361`); then every numeric field is overwritten with the rounded integer mean of the valid ensemble scores (`:177-192`); then up to 4 reflection rounds re-ask the LLM for the JSON (`:222-238`).

## 3. Paper/summary vs code discrepancies
(Compared to `autoresearch_survey/gh_SakanaAI_AI-Scientist.md`; I did not read the paper itself.)
- **"Code is run in a sandboxed environment" (summary line ~51): not true in code.** `run_experiment` uses a bare `subprocess.run(["python","experiment.py",...])` in the host environment (`perform_experiments.py:39-47`). Only mitigation is a README warning (README.md:32) and a community-contributed Dockerfile in `experimental/` (README "Containerization" section). The Dockerfile pins `texlive-full` etc. (head only read) and says nothing about network restrictions [I saw only the first 30 lines].
- **"Reviewer outputs 0-10 scale: soundness, presentation, ... "**: actually mixed scales: Originality/Quality/Clarity/Significance/Soundness/Presentation/Contribution 1-4, Overall 1-10, Confidence 1-5 (`perform_review.py:47-58`).
- **Summary claims reviewer-vs-human correlation 0.18 vs 0.14:** the repo's benchmark script `review_iclr_bench/iclr_analysis.py:170-200` computes accuracy / F1 / AUC / FPR / FNR of the binary Accept/Reject decision, not a score correlation. I did not find correlation code in the file (grep for corr/pearson/spearman returned nothing). The 0.18 figure may come from an analysis notebook I did not open. Unverified.
- **"Reviewer feedback is not fed back to ideation in v1" (summary):** true for `launch_scientist.py`, but `experimental/launch_oe_scientist.py` + `generate_next_idea` do feed the `Overall` score back into the idea archive (`launch_oe_scientist.py:255`, `:390`; `generate_ideas.py:221-225`). The review also feeds the writeup improvement loop (`--improvement`).
- **Novelty check "checks against literature":** it is an LLM reading top-10 abstracts per query; if no verdict is reached in 10 rounds, `novel` stays `False` (`generate_ideas.py:426`, `:485`), i.e. the default is reject (conservative, but it also silently drops ideas on parse/API errors, `:481-483`).
- **README/paper "$15 per paper":** cost is stated in README FAQ (README.md:346-348) but nothing in code measures cost or tokens (no ledger; `llm.py` discards `response.usage`).
- **Parallel open-ended mode shares an idea archive:** `idea_archive` is a plain Python list passed to `multiprocessing.Process` (`launch_oe_scientist.py:319`, `:343`); each process gets a copy, so the "shared" archive and the score back-fill (`:130-134`) are not shared across workers. The `multiprocessing.Lock` protects nothing real [inference from Python semantics; not run].
- Template-embedded disclosure: `templates/nanoGPT/latex/template.tex:176` contains "This work was generated by The AI Scientist", consistent with the license clause 3.2.e.

## 4. Mechanisms worth adopting into custom-harness (ranked by expected value)
Note on honesty: v1 is a weak baseline compared with PLAN.md; most of its value is small, concrete patterns. The reviewer is the most reusable part.

1. **Reviewer protocol pieces: ensemble + meta-review + "negative-bias" system prompt + few-shot + rubric-anchored scales** (`perform_review.py:13-24`, `:65-123`, `:151-192`, `:355-383`).
   - What: N independent reviews at high temperature, an Area-Chair LLM merging them, numeric fields recomputed as ensemble statistics, calibration via an explicitly conservative prior, human review exemplars as few-shot.
   - vs ours: we have only Bradley-Terry K-way ranking for hypotheses (`verify/ranking.py:18`) and no paper/claim-level T5 judge yet (STATUS.md "Next" item 4: judge panel). PLAN §3 L3 specifies a judge panel (multi-family, position swap); this gives a ready rubric and a decision schema.
   - Where: L3 (T5 judge panel) and L4.10 (report quality). Use as T5 only, never sufficient for "verified" (PLAN §5).
   - Improve while copying (see §6): do not round to int, keep per-sample scores and variance, use pairwise/K-way instead of absolute (P5), mix model families, compute decision from scores in code, not from LLM "Decision".
   - Effort S. Reimplement (license; the rubric text is NeurIPS form text, our own wording is trivial to produce).
2. **Reviewer-as-objective benchmark harness** (`review_iclr_bench/iclr_analysis.py:170-200`: accuracy/F1/FPR/FNR vs human accept decisions; `iclr_parsed/`, `ratings_subset.tsv`).
   - What: measures the T5 judge itself against ground truth before trusting it. Directly matches PLAN §8.4/L3 "verifier validation" and C4 (judge agreement reported).
   - Effort S-M; reuse the idea (and, subject to dataset licensing, the data, which I did not check). Reimplement.
3. **Novelty check as a bounded tool-using agent loop with a hard default of "not novel"** (`generate_ideas.py:405-492`, `:285-352`).
   - What: iterative LLM-chosen queries against Semantic Scholar/OpenAlex with a decision token; fail-closed default.
   - vs ours: we have no literature module (STATUS: I3 n/a until literature exists; PLAN L4.3). Useful as the first cut of the hypothesis novelty filter. Must improve: structured JSON verdict instead of substring match on free text (`:448`), log queries/papers as Evidence, store dated snapshots (PLAN L4.3), do not accept an error as a verdict.
   - Where: L4.3/L4.4. Effort S. Reimplement.
4. **Citation grounding by construction: only add BibTeX returned by the search API** (`perform_writeup.py:296-397`, esp. `:369` takes `citationStyles.bibtex` straight from API results, and prompts forbid new bib entries `:434`, `:187`).
   - What: the model cannot invent bibliographic entries; it can only select index numbers from retrieved results. This is the cheapest way to get a large part of PLAN I3 ("every citation resolves to a retrieved doc").
   - Limit: only existence, not that the retrieved paper supports the sentence (the key check at `:34` is a substring test). We should add the "text supports claim" check.
   - Where: L2 integrity audit I3. Effort S. Reimplement.
5. **Failure-feedback loop shape for the code-edit agent** (`perform_experiments.py:116-142`): per-run retry budget that resets on success; stderr tail truncated to 1500 chars; separate max-runs; explicit stop token.
   - vs ours: our `research/modules.py` already has an implement/fix loop (`run_candidate`, `:176`) with deterministic routing; ours runs in an isolated sandbox with hidden test evaluation. Little to adopt except: the idea of feeding the *prior results dict* back into the planning prompt each run (`:66-77`) and requiring the agent to log experiment notes to a `notes.txt` for the writer (`:72`, `:144-164`) — i.e. an agent-maintained lab notebook that is the only input to the writeup. We should instead derive the notebook from Evidence records (PLAN L2), but the "writer reads only notes + code + figures" separation is a good contract.
   - Effort S. Reimplement.
6. **Open-ended archive with reviewer score as fitness** (`generate_ideas.py:178-272`, `launch_oe_scientist.py:255`): minimal quality-diversity loop in text. Only valuable as a negative example of what to do better: archive is pasted as text (context blow-up, no embedding/retrieval), score is the T5 LLM score (Goodharting risk). Our L5/L7 designs already supersede it.
7. **Template contract for fast domain onboarding** (dir with `experiment.py` + `plot.py` + `prompt.json` + seed ideas + `run_0` baseline). Equivalent to our `research/task.py` TaskSpec (52 lines) — see §5. One thing worth borrowing: a *human-supplied seed ideas file* as the idea archive's initial population (`generate_ideas.py:99-102`) and a LaTeX template with built-in disclosure line. Effort S.
8. **LaTeX build-and-repair loop with deterministic linter in the loop** (`perform_writeup.py:77-91`): chktex output as the repair prompt, bounded to 5 rounds. Useful for the report stage if we generate LaTeX. Effort S. Reimplement.

Licensing for copy decisions: custom license grants copy/modify/distribute (Section 2) but (3.1) requires including the complete license copy on distribution, (3.2) use restrictions (surveillance, unlabeled synthetic media, health care, criminal prediction, and the "AI Scientist clause": must disclaim machine generation in any generated manuscript), and (3.3) these restrictions MUST be passed down in any legal agreement governing use/distribution of derivatives. This is incompatible with our PLAN §15 A3 decision (Apache-2.0, unrestricted) if we copy code, because Apache-2.0 does not allow adding use-restrictions to downstream users without making the combined work non-Apache. **Recommendation: reimplement ideas only; copy no code and no prompts verbatim.** Prompt text is code-like content under this license.

## 5. Things custom-harness already does better (with evidence)
- **Sandboxed execution of generated code.** Ours: Docker with no network, caps, non-root, read-only rootfs, gVisor when available (`sandbox/docker.py`, STATUS "Done" L0); LocalSandbox refuses to run untrusted code unless `CHH_ALLOW_UNISOLATED=1` (`research/modules.py:34` `_require_isolation`). Theirs: bare `subprocess.run` on the host (`perform_experiments.py:45`).
- **Immutable evaluator / hidden test.** Ours: hidden-test verification outside the agent's writable area (`research/modules.py:217` `verify`, `research/data.py`), private-data guard (`runtime/template.py`). Theirs: the agent edits `experiment.py`, which itself computes and writes `final_info.json` (`templates/nanoGPT/experiment.py:602-719`); the harness only reads that file (`perform_experiments.py:62-64`). The agent can change what is measured. No hash or diff check on evaluation code anywhere in the repo.
- **Statistics.** Ours: seed bootstrap + paired bootstrap, T2 verdict with CI (`verify/stats.py:20,39,65`), racing and held-out gate (`evolve/selection.py:39,87`). Theirs: 3 seeds for shakespeare_char, 1 for enwik8/text8 (`templates/nanoGPT/experiment.py:686-690`), "stderr" computed as `np.std(v)/len(v)` (line 707-709), which is wrong (should divide by sqrt(n)) and understates uncertainty; no CI or significance test anywhere in the pipeline; improvements are described to the LLM and the writer decides.
- **Claims only from evidence + integrity audit.** Ours: claims created only from Evidence records, audit I1/I2/I4 (`research/modules.py:321` `audit`, `store/evidence.py`). Theirs: the writeup is LLM prose guided by prompts ("Only includes results that have actually been run ... Do not hallucinate", `perform_writeup.py:170`; error_list item "Numerical results that do not come from explicit experiments and logs", `:185`) but nothing deterministic checks numbers against logs.
- **Traces, cost, and budgets.** Ours: full traces, costed failed attempts, budget ledger with hard caps (`runtime/engine.py`, `budget.py`). Theirs: stdout redirected to `log.txt`, Aider chat history file; no token or $ accounting (`llm.py` ignores `response.usage`).
- **Harness evolution, memory, branching.** Theirs: none (v1 does not modify itself). Ours has typed edits, racing, gate, lineage, ledger, calibration (`evolve/`).
- **Concurrency/crash safety.** Ours: per-step checkpoints, exact fork/backtrack (`runtime/engine.py`). Theirs: failure of any stage returns False and abandons the idea (`launch_scientist.py:222-225`, `:256-258`, `:281-282`); no resume.

## 6. Pitfalls, bugs, or anti-patterns seen in their code that we must avoid
1. **Agent controls both code and measurement** (see §5). `final_info.json` is written by the agent-editable `experiment.py`. Any metric in a paper can be inflated by editing the evaluation. We must keep the evaluator outside the agent's write set (we do) and hash-check it.
2. **Review score never gates, and review is on the PDF text of the same LLM-written paper.** The pipeline's only quality signal is a T5 LLM review whose result is stored (`review.txt`, `launch_scientist.py:277`) and not used to filter, and in the open-ended variant is used as fitness (`launch_oe_scientist.py:390`) — Goodhart risk (PLAN P9/P10).
3. **Reviewer implementation bugs.**
   - `temperature` is ignored in ensemble mode: hardcoded `temperature=0.75` (`perform_review.py:160`) even though callers pass 0.1 (`launch_scientist.py:274`). The "temperature=0.1" setting is only used by the meta-review and reflections.
   - `reviewer_reflection_prompt` contains `{current_round}/{num_reflections}` placeholders but is passed unformatted (`:225-227`, template at `:246`).
   - Reflection rounds re-parse a single LLM JSON as the final `review` (`:233`), which can silently discard the numerically averaged ensemble scores written at `:192` (the averaged values only survive via the msg_history text, `:195-209`).
   - Averages are rounded to integers (`:192`), destroying resolution on a 1-4 scale; `Decision` comes from the meta-review LLM not from the averaged `Overall` (`:170`).
   - Reviewer is a "negative" prompt by default (`:136`); useful calibration but the bias is untested in code (the ICLR bench script is run separately).
4. **Fail-silent error handling.** Many `except Exception: print; continue` blocks: novelty-check errors loop on (`generate_ideas.py:481-483`) and then mark `novel=False`; idea generation failures are swallowed (`:162-164`); `papers=None` then iterated in a for-loop in `check_idea_novelty` (`:463-467`: sets `papers_str` and then enumerates `None`, raising TypeError caught by the broad except) — a bug in the "no papers found" path.
5. **Substring/regex control flow on LLM text**: stop tokens "ALL_COMPLETED" (`perform_experiments.py:132`), "I am done" (`generate_ideas.py:157`), "Decision made: novel" (`:448`) and note `"decision made: not novel"` check happens after the `novel` check but `"decision made: novel"` is not a substring of "decision made: not novel", so OK; still fragile. JSON extraction falls back to the first `{...}` match (`llm.py:~310`), which can pick up the wrong object.
6. **Citation check is a substring test** (`perform_writeup.py:34`: `if cite not in bib_text`), so a key that is a prefix of another or appears in a comment passes; and nothing verifies a cited paper supports the sentence.
7. **Hard-coded and global state.** `do_idea` reads the module-global `args.engine` (`launch_scientist.py:254`) rather than a parameter; model-name routing by substring (`'gpt' in model`, `"o1" in model`, `llm.py:80,197`) means any model name containing "o1"/"o3" or "gpt" is routed to those branches [inference from code; e.g. `"gpt" in model` is checked before `o1`].
8. **Resource safety.** `time.sleep(150)` between worker spawns instead of readiness (`:390`); a 2-hour timeout per run (`perform_experiments.py:30`) with no memory/disk/GPU cap; failed run dirs deleted (`:55`), losing forensic evidence that we want in Evidence (PLAN P6).
9. **No baseline re-run, no held-out split**: the baseline `run_0` is a static file; ideas are compared to it by the LLM reading numbers. A different random seed, hardware, or library version changes the baseline silently.
10. **Idea archive is text-only, unbounded** (`generate_ideas.py:116`): the whole archive is concatenated into each prompt; with `num_ideas=50` this scales linearly in prompt size.
11. **License traps** (see §4): restrictive clauses and the mandatory pass-through of use restrictions.

## 7. Verifier / evaluation / safety handling
- **Verifier tier achieved:** effectively T5 (LLM judgment) for paper quality; for experiment results, T6-to-T2-ish at best: seed means from agent-written code with 1-3 seeds, no CI test (`templates/nanoGPT/experiment.py:686-720`).
- **Exploit handling:** none. No quarantine, no perturbation, no hidden evaluator, no check that `experiment.py` still evaluates the same function. Nothing prevents the agent from editing the baseline-comparison text in `notes.txt` (it is in Aider's file set, `launch_scientist.py:179`).
- **Safety/sandbox:** README warning only (README.md:32); community Dockerfile (`experimental/Dockerfile`) is optional and I did not verify network policy. The generated code can install packages, open network connections and spawn processes with the user's privileges and environment (API keys are environment variables inherited by the subprocess, [inference: `subprocess.run` without `env=` inherits os.environ, `perform_experiments.py:45`]). That makes secret exfiltration by generated code possible; our gateway redaction and sandbox env control (`gateway/`, `sandbox/docker.py`) address this.
- **Reviewer validation:** the repo ships a benchmark (`review_iclr_bench/`, `review_ai_scientist/`) that scores LLM accept/reject decisions against ICLR outcomes (`iclr_analysis.py:170-200`), including FPR/FNR. I did not verify the headline numbers; ROC-AUC is computed on binary predictions (`:195-196`), which reduces AUC to a balanced-accuracy-like number, not a ranking quality.
- **Disclosure requirement:** license 3.2.e demands prominent AI-generation disclosure in manuscripts; template includes a line (template.tex:176). Relevant to our F5 ("no external publication without human action").

## 8. Bottom line
- v1 is a linear idea -> Aider-edit -> LaTeX -> LLM-review pipeline with no sandbox, no immutable evaluator, no statistics, and no self-improvement; custom-harness is already ahead on safety, verification, tiers, statistics, and traces.
- Worth re-implementing (not copying): the reviewer ensemble + meta-review + benchmark-against-human-decisions harness (fixed per §6.3), the fail-closed novelty-check loop, API-grounded citation insertion, and `chktex`-in-the-loop LaTeX repair.
- Licensing blocks copying: custom restrictive license with use-restriction pass-through (incompatible with our Apache-2.0 plan); take ideas only.
- Biggest lesson to avoid: agent-editable evaluator plus LLM review as the only quality signal; keep our hidden-test and audit design and add a judge-validation step before any T5 verifier gates anything.
